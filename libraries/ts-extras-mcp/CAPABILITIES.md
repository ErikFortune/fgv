[libraries/ts-extras-mcp](https://github.com/ErikFortune/fgv/tree/release/libraries/ts-extras-mcp)

A Result-integration boundary over [`@modelcontextprotocol/sdk`](https://github.com/modelcontextprotocol/typescript-sdk) (`^1.29.0`, a direct dependency) that connects to an MCP (Model Context Protocol) server, discovers its tools, and **adapts each into an `AiAssist.IAiClientTool`** (from `@fgv/ts-extras`) so it drops directly into `AiAssist.executeClientToolTurn` — making any MCP server's tools callable across all four cloud providers with no per-provider work. All SDK imports are isolated to one file so the announced SDK v2 rename is a one-file change.

| Function | Return |
|---|---|
| `createStdioTransport({ command, args?, env?, cwd? })` | `Result<IMcpTransport>` |
| `createHttpTransport({ url, headers?, fetch?, authProvider? })` | `Result<IMcpTransport>` — every HTTP request of the session (each `POST`, the standalone `GET` event stream, the close's `DELETE`, and every OAuth discovery/registration/token request) goes through `fetch`. **Pass `SaferFetch.createGuardedFetch({ addressGuard: SaferFetch.blockPrivateNetworks(), headersTimeoutMs })` from `@fgv/ts-extras`**, with `headersTimeoutMs` at least your longest MCP request timeout: a JSON-response server holds a slow `tools/call`'s headers until the tool finishes, and the guarded fetch's headers deadline (default 10 s) then fails it as `timeout` whatever `timeoutMs` the call had. Without a guarded fetch, `globalThis.fetch` is used, with no address guard. **To bound what a server can send, give the guarded fetch `maxResponseBytes`:** it applies to each HTTP response separately, and a `POST`'s answer past it fails that request promptly as `egress-blocked` with reason `'too-large'` — a JSON body refused on its `Content-Length` or when the count trips, and an SSE answer when the count trips mid-stream (the SDK reports an SSE read error only to its `onerror`, so the package's egress fails the request the body belongs to itself; the session stays usable). The standalone `GET` event stream is counted **per connection**: when one passes the cap it is cut off and logged at `detail`, and the SDK reconnects it at once with a fresh count — so the cap bounds each connection, not the session's total. Size it above your largest expected `tools/list` page or tool result. `authProvider` is the SDK's `OAuthClientProvider` (exported as `McpOAuthClientProvider`): its interactive steps (`state`, `saveCodeVerifier`, `redirectToAuthorization`) run **only inside `connectMcpSession`** and are refused on a later call, on the SDK's background reconnect of the event stream, and on close (→ `unauthorized`); a flow started inside a connect that then times out or aborts can pass `state` and `saveCodeVerifier` and be refused only at `redirectToAuthorization`; an authorization URL that is neither `https:` nor loopback `http:` is always refused; exchanging the code with the SDK's `auth()` is the consumer's — pass the guarded fetch as its `fetchFn`; discovery, registration, token refresh, `saveTokens` and `invalidateCredentials` run wherever the SDK needs them. Static `headers` are applied by the package only to requests whose URL is on the MCP endpoint's origin — never to the authorization server or any other origin — and there replace a header of the same name (a static `Authorization` overrides the OAuth bearer token); without a consumer `fetch` those requests refuse redirects, with a guarded fetch its default `'reject'` holds, and `validate-each-hop` carries a static header across a redirect unless it is in `sensitiveHeaders`; a header name given twice in different letter cases is refused. `headers` is copied when `createHttpTransport` is called, so later changes to the caller's record have no effect. The provider is wrapped in a forwarding facade, a different object from the consumer's provider (frozen providers and private fields work; optional members the provider lacks stay absent), and a provider or header that throws while the transport is built fails it with fixed text. |
| `createCustomTransport(sdkTransport)` | `Result<IMcpTransport>` — wraps any pre-built SDK client transport (e.g. `InMemoryTransport` for tests against an in-process server), typed structurally as `IMcpSdkTransport`. It must be fresh (refused if it already has a `sessionId`, which would make the SDK skip `initialize`), and its `close()` must call `onclose`. The interface declares the `onclose` / `onerror` / `onmessage` slots the SDK assigns, so a consumer's own transport class can be written against it. Every transport handle is single-use. |
| `connectMcpSession({ transport, clientName?, clientVersion?, logger?, onClose?, onToolsChanged?, timeoutMs?, signal? })` | `Promise<DetailedResult<IMcpSession, McpFailureReason>>` |
| `closeMcpSession(session)` | `Promise<Result<true>>` — on a Streamable-HTTP session, first sends the `DELETE` that ends the session on the server (the SDK's `terminateSession()`), best-effort and bounded to 2 s: a 405, a failure, a dropped connection or silence never fails the close or holds it longer, and is logged at `detail`. Stdio and custom transports close as before. |
| `listMcpTools(session, options?)` | `Promise<DetailedResult<ReadonlyArray<IMcpToolDescriptor>, McpFailureReason>>` (follows the SDK's `nextCursor` for the full catalog). `options` is an `IListMcpToolsOptions`: the per-request options (applied to **each page**) plus two opt-in bounds over the **whole** listing, neither with a default — `maxPages` (a positive integer: a listing whose page `maxPages` still carries a `nextCursor` fails without requesting another; exactly `maxPages` pages succeed) and `maxTotalMs` (an overall deadline from the call, checked before each page and aborting the page in flight, which sends the server `notifications/cancelled`; same range as `timeoutMs`). Exceeding either fails the listing as `limit-exceeded` with `limit: 'maxPages' \| 'maxTotalMs'`; the pages already read are discarded, **never returned as a truncated catalog**. Each descriptor carries `name`, `title?` (the tool's `title`, else `annotations.title`; kept only when it is one printable line), `description`, `inputSchema` and `outputSchema?` as raw JSON (not parsed; omitted when an own `__proto__` key reaches the package — though the SDK's own `tools/list` parse already drops one at the schema's top level or among its `properties` names), normalized `annotations?`, and normalized `execution?` — `{ taskSupport?: 'forbidden' \| 'optional' \| 'required' }` (`McpTaskSupport`; absent means `'forbidden'`), converter-read, with an unknown value or a non-object blob dropped and logged at `info` in fixed text. The SDK's own `tools/list` schema already rejects a `taskSupport` outside that vocabulary, failing the page as `protocol` before it reaches the package. `_meta` is not carried. |
| `callMcpTool(session, name, args, options?)` | `Promise<DetailedResult<IMcpToolCallResult, McpFailureReason>>` — `{ content, blocks, structuredContent? }`. `blocks` is every content block converter-validated into the `McpContentBlock` union (`text`, `resource_link`, embedded text or blob `resource`, `image`, `audio`, and `unknown` for an unknown type or a malformed block, which never fails the call). Image, audio and blob blocks carry `mimeType` + decoded `byteLength`, and their base64 `data` only with `options.includeMediaData: true`. A field the projection never prints does not cost a block its body: an embedded resource whose `uri`, or an image or audio block whose `mimeType`, is missing or not one printable line keeps its text or data with that field absent (a `resource_link`'s `uri` is still required — it is the point of the block). Base64 is accepted in the standard or URL-safe alphabet with optional padding; line-wrapped base64 is treated as malformed (the block becomes `unknown`). A block's `annotations` (`audience`, `priority`, `lastModified`) and `_meta` are not carried. `structuredContent` is carried when it is JSON, and refused whole (logged at `info`) when it holds an own `__proto__` key. `content` is the text projection (`text` → its text; `resource_link` → `[resource_link: <uri> (<name>)]`; embedded text → its text; media and unknown → `[<type> block]`), with every server string interpolated into a generated placeholder (a link's URI or name, a `blockType`) validated as one printable line; text and embedded-text bodies are free text, projected verbatim. `isError: true` → failure with that projection verbatim, never swallowed. **A `resource_link` URI is never followed:** it is server-supplied, so fetch it only through your own egress guard. |
| `adaptMcpTools(session, { logger?, schemaKeywords?, patternValidator?, discovery? })` | `Promise<DetailedResult<{ tools: ReadonlyArray<AiAssist.IAiClientTool>; skipped: ReadonlyArray<IMcpSkippedTool> }, McpFailureReason>>`. `discovery` is the `IListMcpToolsOptions` its `listMcpTools` runs with, so `maxPages`, `maxTotalMs`, `timeoutMs` and `signal` bound discovery here too. Each skip is `{ name, kind, reason, schema }`, with `kind: McpSkipKind` — `'schema'`, `'wire'` or `'task-support'`. |

**Per-request options (`IMcpRequestOptions`; `callMcpTool` takes `IMcpCallToolOptions`, which adds `includeMediaData`):** `timeoutMs` (SDK default 60 000), `signal`, `onProgress`, `resetTimeoutOnProgress`, `maxTotalTimeoutMs`, mapped onto the SDK's `RequestOptions`. On `connectMcpSession`, `timeoutMs` and `signal` bound the **whole** connect — transport start, `initialize`, and sending `notifications/initialized`, which the SDK's own request options do not cover — and a lost or failed connect starts closing the transport without waiting for it, so teardown can finish after the connect has returned. `timeoutMs` applies per request — per page in `listMcpTools`. An abort or a `timeoutMs` expiry sends the server `notifications/cancelled`, so the request does not run on as an orphan; a `maxTotalTimeoutMs` expiry does not (the SDK fails it locally without a cancellation). Adapted tools forward the turn's `signal` (`IAiClientTool.execute`'s context) to `callMcpTool`, so cancelling an `executeClientToolTurn` turn cancels the MCP request.

**Failure kinds (`McpFailureReason`, the `DetailedResult` detail):** the classification is total and keys on the SDK's error class, JSON-RPC code, HTTP status, the session's observed close and the identity of the call's own abort reason — never message text. Branch on `kind`; do not parse messages.

| kind | SDK signal |
|---|---|
| `tool-error` | `CallToolResult.isError: true` — message is the tool's text, unprefixed |
| `timeout` | `McpError` code `-32001` (`RequestTimeout`), including `maxTotalTimeoutMs` |
| `aborted` | the caller's signal fired first — decided by the identity of the abort reason this package issued, because the SDK reports an abort with the *timeout* code |
| `not-connected` | the session's close was observed: the SDK's `ConnectionClosed` (`-32000`) or untyped "Not connected", both raised only after `onclose` fires (a server's own `-32000` on an open session is `protocol`). During the handshake any `-32000` is `not-connected` |
| `session-expired` | `StreamableHTTPError` 404 on an established session (during the handshake a 404 is `transport`) |
| `unauthorized` | HTTP 401 / 403, the SDK's `UnauthorizedError` (including an interactive authorization refused outside the connect), or an `OAuthError` from the authorization server; carries `status` when there was one, and `resourceMetadataUrl` — the `resource_metadata` URL of the endpoint's latest `WWW-Authenticate` challenge, kept only when it is an `http(s)` URL on one printable line. Server-chosen: fetch it only through the guarded fetch. **HTTP-error and OAuth-error text never reaches a failure message** — this kind, and any failure from an HTTP or OAuth error, reads as kind + status (`unauthorized (HTTP 401)`, `transport (HTTP 500)`); `tool-error` and `protocol` messages carry server text by design, and the SDK's other auth errors can name a server-chosen URL |
| `egress-blocked` | the transport's guarded `fetch` refused the request (`SaferFetch.GuardedFetchError`); carries `reason`, the refusal's `FetchFailureReason` kind, never its URL. A configuration refusal — retrying cannot help. A guarded fetch's `timeout` (headers deadline) is `timeout`; its `network` / `aborted` / `unknown` are not refusals and classify as before (`transport`, or `not-connected` once closed) |
| `protocol` | any other `McpError` — a JSON-RPC error from the server, carrying `code` — or a response that failed the SDK's result schema (zod's error, no `code`) |
| `transport` | the catch-all: any other HTTP status (carries `status`), network or child-process I/O failures, untyped SDK errors (including the handshake's protocol-version refusal) |
| `invalid-handle` | a session/transport handle not produced by this package, or a transport handle already used by an earlier connect |
| `invalid-options` | a `timeoutMs` / `maxTotalTimeoutMs` / `maxTotalMs` that is not a positive finite number ≤ 2³¹−1 (`setTimeout` would otherwise fire it after 1 ms), or a `maxPages` that is not a positive integer; reported before anything is sent |
| `limit-exceeded` | a bound the caller set over a paged `listMcpTools` (or `adaptMcpTools`'s discovery) was exceeded; `limit` is `'maxPages'` or `'maxTotalMs'`. The listing fails whole — nothing is truncated — and the session stays usable. A caller's own abort that lands first is still `aborted`, and a page's own `timeoutMs` that fires first is still `timeout` |

**Tool-list changes:** `connectMcpSession({ onToolsChanged })` fires on each `notifications/tools/list_changed`. It is an observation — the package never re-lists; call `listMcpTools`. Never once `closeMcpSession` is entered (an HTTP close can hold the connection open for 2 s) or after the connection closes, never for a failed connect; any that land during the connect are delivered as one call, just after the session is returned. Contained like `onClose`.

**Close observation:** `connectMcpSession({ onClose })` fires once when the connection closes, for any reason (including `closeMcpSession`); never for a failed connect; a throwing callback, or an `async` one that rejects, is contained and logged. Reconnect policy stays with the consumer — the package has no pool or reconnector. A Streamable-HTTP server restart is not a close; the next call reports it as `session-expired` when the server answers 404.

**Graceful degradation (load-bearing):** `adaptMcpTools` never fails the whole catalog over one bad schema. A tool whose `inputSchema` is outside the `JsonSchema.fromJson` subset (`pattern` unless `options.patternValidator` is supplied, a *general* union, a remote or recursive `$ref`, an `enum` mixing value types, an object or array `const`, … — numeric and boolean `enum`s, a scalar `const` (enforced), `{}` (any value), the nullable spellings `type: [<type>, 'null']` and `anyOf`/`oneOf` `[T, {type:'null'}]`, local `$ref`/`$defs`, and a schema-valued `additionalProperties` on an object with no declared properties and no keyword constraining its key set (`patternProperties`, `propertyNames`, `unevaluatedProperties`, `dependentRequired`, `dependentSchemas`, `dependencies`, `min`/`maxProperties`) are in the subset and adapt fine; zod `.catchall()` shapes — declared properties plus a value schema — are still skipped) is **excluded** from `tools` (the model is never offered a tool whose args we can't validate), and so is a tool whose schema the **target wire cannot carry**: `adaptMcpTools` admits each parsed schema against `options.schemaKeywords`, the keyword-capability table of the wire the tools will be sent on (`AiAssist.clientToolSchemaKeywords(descriptor, { model, endpoint, verifiedEndpoint })` from `@fgv/ts-extras`, given exactly what the turn is sent with), **defaulting to the conservative `JsonSchema.unverifiedWireSchemaKeywords`** — so with no option a tool with an untyped `{}` parameter (pydantic `Any`) is skipped, and with the Anthropic-tools table it is adapted, rather than one such tool failing every request on a wire that refuses it. Admission is a check only: the tool keeps its parsed schema, and the request path adapts it once, on send. A table that does not match the wire is caught at turn creation: `executeClientToolTurn` returns a `Failure` naming the tool, the path and the wire, and sends nothing. **Task support:** a tool declaring `execution.taskSupport: 'required'` is skipped whatever its schema — it must be invoked as an MCP task, which this client cannot drive, and a plain call to it fails (the SDK refuses one as `protocol`, `-32600`, for the tools of the most recent `tools/list` page it parsed — its task-required cache is reset on every page — and otherwise the server does); `'optional'`, `'forbidden'` and an undeclared value are adapted and called normally. Every skipped tool is **surfaced structurally** on `skipped` (name + `kind` — `'schema'` for a schema outside the subset, `'wire'` for one the target table refuses, `'task-support'` for a task-required tool — + reason + raw schema; branch on `kind`, never on `reason`), and — when a `logger` is supplied — **NOISY-warned** with all three (control characters in that log line are escaped as `\uXXXX`, so a server-supplied name or schema cannot break or forge it; the structured `skipped` record is left as sent). **`pattern`:** this package never compiles a server's regular expression, so a tool using `pattern` is skipped by default; pass `patternValidator` (a `JsonSchema.SchemaPatternValidator`, ideally on an RE2-class engine — `re2PatternValidator` from `@fgv/ts-extras-re2`) and it is handed to `JsonSchema.fromJson` — the tool is adapted, its predicate enforces the pattern on every call before the server sees it, and the wire carries the server's source where the target table passes `pattern` (a `Constraints: pattern …` description elsewhere); a validator `Failure` skips the tool with its reason. The `samples/testbed` `mcp-probe` scenario points it at any MCP server and prints a compatibility report (configure via `MCP_PROBE_URL` or `MCP_PROBE_COMMAND`).

**Explicitly NOT in scope:** browser sibling (`@fgv/ts-web-extras-mcp`), MCP resources / prompts / sampling, a helper around the SDK's OAuth `auth()` flow (exchanging the authorization code after a redirect is the consumer's), closing DNS rebinding (the guarded fetch documents it as open), following `resource_link` URIs, handing rich blocks (rather than the text projection) through `adaptMcpTools` into the ai-assist round-trip, cross-server tool-name namespacing. Widening `JsonSchema.fromJson`'s subset lives in `@fgv/ts-json-base` (its `CAPABILITIES.md` lists what is accepted; `docs/FUTURE.md` lists what is deferred and why). **Security:** `createStdioTransport` spawns a consumer-supplied command as a subprocess — a trust boundary; never source the command from untrusted input.

## Decision shortcuts

- **Making an MCP server's tools callable from an ai-assist tool-use conversation?** → `@fgv/ts-extras-mcp` (Node). `connectMcpSession` → `adaptMcpTools(session, { logger, schemaKeywords: AiAssist.clientToolSchemaKeywords(descriptor, { model }) })` → hand `result.tools` (`AiAssist.IAiClientTool[]`) to `AiAssist.executeClientToolTurn({ ..., clientTools: result.tools })`. `adaptMcpTools` gracefully degrades: tools whose `inputSchema` is outside the `JsonSchema.fromJson` subset, that the target wire cannot carry (default: the conservative table), or that require MCP task execution land in `result.skipped` (name + `kind` + reason + raw schema) and NOISY-warn rather than failing the catalog. Bound discovery with `adaptMcpTools(session, { discovery: { maxPages, maxTotalMs } })`, and response size with the guarded fetch's `maxResponseBytes`. Transports: `createStdioTransport({ command, args })` (spawns a subprocess — trust boundary), `createHttpTransport({ url, headers, fetch, authProvider })` — pass a `SaferFetch.createGuardedFetch` as `fetch` for SSRF protection — or `createCustomTransport(sdkTransport)` for any SDK transport (e.g. `InMemoryTransport.createLinkedPair()` in tests). Bound or cancel calls with `callMcpTool(..., { timeoutMs, signal })`; branch on the failure's `McpFailureReason.kind`, never on its message text. Use the `samples/testbed` `mcp-probe` scenario (`MCP_PROBE_URL` / `MCP_PROBE_COMMAND`) to get a compatibility report for any server. **Don't hand-roll an MCP client or a JSON-Schema→client-tool adapter.**
