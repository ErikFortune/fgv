### `ai-assist-model-catalog-2026-09` ✅ (shipped 2026-09-24 via #692)

**Status: ✅ shipped via [#692](https://github.com/ErikFortune/fgv/pull/692); live-verified by the user's testbed run on 2026-09-25.**
Artifacts at `.ai/tasks/completed/2026-09/ai-assist-model-catalog-2026-09/`. *Written anticipating
merge, per the artifact protocol.* `result.md` §1 is the cited id table, and §6a records the live
run.

**Mission.** A provider-line rotation for OpenAI, Anthropic, Gemini and xAI. Every identifier had
to come from a fetched documentation page, cited by URL and date. Search was allowed only for
finding pages.

**What shipped.** OpenAI's tiers moved to the GPT-6 line: `gpt-6-luna`, `gpt-6-sol` and
`gpt-6-astra`. GPT-6 reuses the 5.6 names at different rungs, so `@openai:flagship` now names Sol.
The image alias moved to `gpt-image-2.5-sunburst`. Gemini flash moved to `gemini-3.8-flash` and
flash-lite to `gemini-3.5-flash-lite`. xAI's flagship moved to `grok-4.7` and imagine to
`grok-imagine-image-2.0`, ahead of `-quality` retiring on 2026-11-02. New `idPattern` rules cover
`gpt-6`, `grok-4.7` and `grok-4.6`. Before `/^gpt-6/`, `listModels` returned GPT-6 ids with no
capabilities at all. The unions track the new ids and drop two deep-research ids that were already
shut down.

**What changed shape along the way.**
- **Anthropic was held, not rotated.** `claude-opus-5-5` and `claude-fable-5-1` return a 400 on a
  forced `tool_choice`, which is the whole of `anthropic-tool-forced` structured output. Rotating
  would have broken structured output on the advanced tier. Filed as a P2.
- **A capability flag needed code to be true.** `grok-imagine-image-2.0` accepts `quality`, but
  neither xAI image builder had ever sent the resolved `quality` option. The builders now send it when the model's capability
  declares it.
- **The repo-wide test caught the predicted casualty.** `samples/testbed` pinned the old concrete
  ids. Only the pins were updated.
- **The live run turned the rotation into one new capability.** `gpt-6-astra`, `grok-4.7` and
  `gemini-3.1-pro-preview` reject thinking `'none'`. The user chose to roll forward. Descriptors
  now declare `thinkingRequiredModelPrefixes`, and `IThinkingConfig.onUnsupported` controls what
  happens: `'none'` is sent as `'low'` by default, and `'fail'` refuses the call before anything is
  sent. The canaries gained strict-none probes that fail if that list ever drifts from the
  providers.
- **The manual-axes TECH_DEBT entry gained a third axis:** the per-model capability declarations.

**Sourcing lesson.** Use `WebFetch` for reachability, then quote ids from the raw page via `curl`.
A summariser rendered one image model's display name as if it were an id.
`docs.anthropic.com` is still blocked, which step zero said should stop the sweep. It proceeded
because `docs.claude.com` now redirects to `platform.claude.com`, which is reachable; `result.md` §0
records the call.

**Open.** The P2 on non-forcing Anthropic structured output, which unblocks the Anthropic
rotation. The P3 on the image-knob widenings, the `/^gemini-3/` over-match, and two review-loop
loose ends (the endpoint-agnostic `'other'`-block effort check; `gemini-2.5-pro` gated but absent
from its union). Copilot's loop stopped at 7 rounds on diminishing returns.
The completion response does not report a clamped `'none'`; a caller who needs the guarantee
passes `onUnsupported: 'fail'`.

### `prompt-assist-qualifier-stability` ✅ (shipped via #689)

**Status: ✅ shipped via [#689](https://github.com/ErikFortune/fgv/pull/689).** Artifacts at
`.ai/tasks/completed/2026-09/prompt-assist-qualifier-stability/`. *Written anticipating merge, per
the artifact protocol.*

**Mission.** Two PersonAIlity asks, both additive, both inside `@fgv/ts-prompt-assist`. **A:**
`IPromptResolveObservation.composition?`, so an observer-backed prompt browser sees section maps
and `cacheFindings` for every resolve. **B:** a qualifier axis declares its stability
(`IExpectedQualifierAxis.stability?`, default `'per-request'`), and the D2 conditional-body check
refutes a claim only when a conditioning axis is declared less stable than the claim. The finding
names the axis.

**Design decided at brief time.** Stability is declared on the axis. A call-site override that
survives D2 was refused on the `adaptOptionalToNullable` precedent, because it would make a verified
diagnostic unfalsifiable. A per-resolve map was refused as a second source of truth. For Ask A,
`cacheFindings` was deliberately not hoisted onto the record.

**The finding that kept it cheap.** `IConditionMatchResult` never names its qualifier. The join is
`candidateIndex` → prompt-assist's own `ConditionSetDecl`, keyed by qualifier name, so
`libraries/ts-res/` is untouched.

**What changed shape along the way.**
- **Losing candidates.** Crediting only the winners' axes would have *introduced* a false
  `'frozen'`. Take a winner conditioned on a frozen-declared axis beside a losing partial on an
  undeclared one: the old check refuted that body only because any conditional winner put it at
  `'per-request'`. Once the body is conditional, the axes of losing candidates and `matchAsDefault`
  winners are now folded in. The first `code-reviewer` pass missed this; it surfaced while
  `result.md` was being written.
- **Downgrade target.** Refuted claims now drop to the body's conditioning level instead of always
  `'per-request'`. With nothing declared the two are identical.

**Compatibility.** Undeclared axes reproduce every prior refutation exactly in `slot`, `claimed`
and `downgradedTo`, pinned by tests. `detail` changed by design: it now names the axis. All
pre-existing tests pass unmodified. The repo-wide `rush test` is green, and no downstream fixture
pinned the old boundary.

**Open.** A body whose winners include no conditional `'match'` (all unconditional, or conditional
only as `matchAsDefault`) is still blind to a volatile competing candidate.
The gap predates this stream. Closing it adds refutations to bodies that are not refuted today, so
it needs its own decision.

### `ai-assist-streaming-cache` ✅ (shipped via #688)

**Status: ✅ shipped via [#688](https://github.com/ErikFortune/fgv/pull/688).** All acceptance
criteria verified, `code-reviewer` approved with no P1/P2 findings, repo-wide `rebuild` + `test`
green. Exit artifact at `.ai/tasks/completed/2026-09/ai-assist-streaming-cache/`.

*Written anticipating merge, per the artifact protocol — a PR cannot observe its own merge, so an
author-time-accurate marker is guaranteed wrong on landing.* Layer 2 (Copilot / CodeRabbit) runs on
#688; it had not run when the branch was first pushed.

**Mission.** Thread `cache?: IAiCacheRequest` through the **streaming** request paths of
`@fgv/ts-extras/ai-assist`, as `completionClient` already threads it through the non-streaming ones,
so a tool-augmented or streamed turn can carry system-prompt cache breakpoints and a routing key.

**Origin.** A PersonAIlity ask, verified against our own source before acting (both sides have
shipped a wrong sweep before). **All their claims held.** They reported it against compiled
`5.1.0-56` rather than declarations — their `#664` lesson — and source agrees with dist.

**The gap, and it is wider than the ask.** `cache?: IAiCacheRequest` appears in exactly one file in
the packlet: `completionClient.ts`. `callProviderCompletion` honors it and `callProxiedCompletion`
forwards it; **`callProviderCompletionStream` and `executeClientToolTurn` have zero `cache`
references between them.** So it is not that the tool turn is missing what its sibling has — **no
streaming path can send a cache plan at all**, and a tool-less streaming turn is equally unable to.
The two are separate request paths (`streamingClient.ts:63–72` documents that client tools
deliberately do not flow through `callProviderCompletionStream`), so both need threading; fixing
only the one they hit leaves the sibling hole open.

**Package surface:** `ts-extras/ai-assist` — `streamingClient.ts`, `clientToolContinuationBuilder.ts`
and the per-provider stream builders they call. An **active surface**, so additive and free.

**Out-of-scope:** `completionClient`'s existing behaviour (it is the reference, not the target); any
change to `IAiCacheRequest`, `validateAiCacheRequest` or the `supportsPromptCache*` predicates;
`ts-prompt-assist`, consumed unchanged. The brief additionally asked that, if the **proxied**
streaming path could not honor `cache` without a proxy-side protocol change, it refuse explicitly
the way #679 refused `endpoint`. **It ships forwarding `cache` as a plain `body.cache` field
instead** — a considered reversal, not an oversight: the two parameters fail differently when a
proxy ignores them. `endpoint` names *where the request must go*, so ignoring it misdirects the
prompt to a destination the caller excluded; `cache` names an optimization, so ignoring it yields
exactly the request a caller who omitted `cache` would have sent. Forwarding also keeps the
streaming proxy symmetric with `callProxiedCompletion`, which already forwards the field.
**Caveat, carried forward from the non-streaming proxy:** no shipped proxy implementation is known
to read `cache` yet, so a caller relying on it should confirm their proxy forwards it through to
`callProviderCompletionStream`. Full reasoning in `result.md`.

**Acceptance criteria.** `cache?` on both entry points, honored end to end; validation **per round**
against that round's own `system`, failing the round rather than dropping the plan; breakpoints and
routing key **independently gated** (the comment at `completionClient.ts:915` records why gating
them together was wrong); a descriptor supporting neither gets a **byte-identical** body to the
no-`cache` case. **Tests assert the request body, not success** — #679's lesson, since a dropped
parameter still returns 200. Plus the repo gates, including a repo-wide `rush test`: this widens
what these functions *accept* without moving a signature, which a rebuild cannot see.

**Parallel with:** `agent-tasks-t4` (different package, different base branch, no code overlap) —
both touch `LIBRARY_CAPABILITIES.md` and this file, **own section only**.

**Branch:** `claude/ai-assist-streaming-cache`, off `release` at `af05bb319`. **PRs into `release`.**

**Artifact pointer:** `.ai/tasks/completed/2026-09/ai-assist-streaming-cache/`.

### `filetree-atomic-write` ✅ (shipped via #681 and #682)

**Status:** ✅ shipped — **written anticipatorily, and across two hops**, per the artifact
protocol's "a PR anticipates its own merge". **F1 — contracts and session implementation** merged
to `integration/filetree-atomic-write` via
[PR #681](https://github.com/ErikFortune/fgv/pull/681). **F2 — Node implementation and
process-crash qualification** via [PR #682](https://github.com/ErikFortune/fgv/pull/682) into that
same integration branch, which also carries this stream's `active/` → `completed/2026-09/`
migration. The integration branch then squashes to `release` as
one landing, opened by the orchestrator — that promotion PR belongs to no single version and is
deliberately absent from this stream's `prs`. **Neither hop had completed when this entry was
written**; F1 alone does not reach `release`.
**Package surface:** `@fgv/ts-json-base` (`file-tree` packlet) — and nothing else.

**What shipped.** An **optional atomic-write capability** on `FileTree`:
`IAtomicFileTreeAccessors` / `IAtomicFileTreeDirectoryItem`, the `AtomicWriteGuarantee`
vocabulary, classified `IAtomicWriteReceipt` / `IAtomicWriteFailure`, `isAtomicAccessors` /
`isAtomicDirectoryItem`, `DirectoryItem` delegation, `InMemoryTreeAccessors` at `'session'`, and
`FsFileTreeAccessors` implementing the design's six-step temp/flush/rename/directory-flush
protocol over a **typed internal filesystem seam** that is not re-exported from either barrel —
so the fault behaviour is testable without publishing a fault-injection knob that could never be
retracted. Ordinary `saveFileContents` / `saveFileBytes` are untouched. Also
`cleanupAtomicTemporaries` on both atomic interfaces — reclamation at reopen was in F2's brief;
what needed a judgement was making it a **required** member, which the brief's "no required member
on an existing base interface" clause is read as not covering, since these are the optional
capability interfaces F1 introduced and no version has published. §8.2 step 6 requires
reclamation at exclusive reopen, and without a caller-reachable entry point a consumer would have
had to depend on the reserved temporary-naming format.

**The idea worth carrying elsewhere: a durability claim is refused unless the root can be
*positively identified* as one the suite actually ran on.** Not a denylist, not a platform string,
not one successful probe. Linux on ext2/ext3/ext4 or tmpfs advertises
`['session', 'process-crash']`; everything else advertises nothing and **refuses** rather than
performing a weaker write. The same posture governs `visibility`: `'unchanged'` is claimed only on
positive evidence that the rename was rejected before touching a directory entry, so `ENOSPC`,
`EDQUOT`, `EIO`, an unrecognized errno and an *absent* errno all classify `'unknown'`.

**That rule cost the stream its macOS support, and that is the rule working.** A1 named macOS in
the intended matrix. Linux's `statfs` magic is a stable filesystem identifier; darwin reports a
mount-table index and Node exposes no equivalent of `f_fstypename`, so a darwin root cannot be
identified from inside the package and is refused. **`@fgv/ts-agent-tasks` T3's durable path is
therefore unblocked on Linux only** — missing platform evidence is not "passed". *(A1 amended
2026-09-22: darwin is dropped from the intended matrix rather than deferred, and no darwin slice is
queued — a containerized consumer executes against the Linux kernel, so the gap is never on the
execution path. The live question is the filesystem: `overlayfs` is deliberately unqualified, so a
container root on the writable layer is refused while a named volume or Linux bind mount
qualifies.)*

**Evidence.** Fault injection at every protocol boundary, wrapping the **real** filesystem so
that everything preceding an injected failure genuinely happened on disk. Subprocess tests in
which a child running the real protocol **`SIGKILL`s itself** at each of seven boundaries —
self-inflicted, so synchronization is exact rather than a sleep — on ext4 and tmpfs, with the
prediction written into `state.md` before the first run. Then twelve protections neutered one at
a time to confirm the intended test actually goes red. **What none of it establishes is
OS-crash or power-loss survival**: a process-kill leaves the page cache intact, so flushed and
unflushed bytes are indistinguishable to every test here, and the `fsync` calls are verified to
be *made* at their points in the sequence rather than to have reached a device.

**Vocabulary reconciliation — the reason for the integration branch.** F1 declared 16 union
members and exercised 5, so F2 held an explicit license to revise rather than inherit.
`IAtomicWriteFailure.stage` **loses `'cleanup'`**: with the protocol implemented it has no
producer and cannot honestly acquire one, since a cleanup problem is reported in the message and
never replaces the classification of the failure that caused it, and a successful commit leaves
nothing to clean up. All four `AtomicWriteGuarantee` members were **kept**, on a distinction
worth reusing — *`guarantee` is an **input** vocabulary, where a member is witnessed by a
**refusal** as much as by a receipt (A1 requires `'os-crash'` and `'power-loss'` to be expressible
so they can be rejected); `stage` is an **output** vocabulary, where a member with no producer is
dead.* 15 declared members, 0 unexercised.

**Three defects found by how it was tested, not by reading it.** (1) `errnoOf` used
`error instanceof Error`; Node's `fs` builds errors in its own realm, so in any `vm` context or
test sandbox an ordinary `ENOENT` became `'UNKNOWN'` — and a rename failure that was provably
`unchanged` would have been reported `unknown`. (2) Widening an interface without widening its
type guard is **invisible to the compiler**, because the guard's own assertion suppresses the
check: `isAtomicAccessors` still checked two of three members, so the delegating call threw a
`TypeError` instead of returning a `Result` (caught as a P1 by `code-reviewer`). (3) Two mutations
did not compile and reported "nothing went red" — indistinguishable from a verified protection,
and they were the two *flushes*; recorded as unverified and redone rather than counted.

**Open follow-up, dispositioned twice.** `createChildFile` / `createChildFileBytes` still accept a
separator-bearing child name where `writeChildAtomically` rejects one. Routed to
`docs/TECH_DEBT.md` as a P3 rather than folded in: it is a behavior change on two established
methods of a stability-obligated package, and wants to be a deliberate decision rather than a
rider on an unrelated stream.

**Artifact pointer:** `.ai/tasks/completed/2026-09/filetree-atomic-write/`.

**C2 shipped — [PR #669](https://github.com/ErikFortune/fgv/pull/669) merged into `release`.** The

**One deliberate deviation from a literal reading of §9's D2, surfaced rather than silently
resolved.** `IPromptSection` carries no `candidateIndex` — template sections come from the
*joined* body of every matched candidate, rendered as one Mustache template, so a per-section
attribution back to "which candidate produced this text" is not data `IPromptComposition` has.
Applied D2 at the coarser granularity the data actually supports: if *any* candidate matched with
a non-empty, non-`matchAsDefault` condition set, every `'template'` section in the resolve is
downgraded together.

**D5's exact algorithm was underspecified in §9.** Implemented as: fold sections into stability
runs; the cacheable prefix is the leading run sequence that stays non-increasing and above
`'per-request'`, stopping at whichever comes first — the first `'per-request'` section, or the
first upward transition (already reported by D4). Left the C3 slice its own job — sizing which
≤2 breakpoints to *emit* is a different question than "how big is the biggest reliably-cacheable
prefix", and D5 does not replicate §5's nested-breakpoint-count algorithm.

**A converter gap the design didn't name, caught by an end-to-end test, not by the type system.**
`IPromptSlot.cacheStability` round-trips through `descriptorConverter.ts`'s hand-declared
`slotConverter` — which silently dropped `cacheStability` on any load through
`PromptStoreFixture`/`FileTreePromptStore` until a new `EnumConvert.promptCacheStability` was
added to `enums.ts` and wired into `slotConverter`'s field list. Kept as a lesson: a new declared
field on a loader-facing type needs its converter updated in the same change, and a same-file
type check cannot see that gap — only a test that exercises the actual load path can.

**Open questions, all closed.** OQ-1 (xAI's cache surface) settled by a live `xai-cache-probe`
testbed run: both routes cache ~99% of a stable prefix, under *different* field names per route,
and neither reports a cache **write** — so xAI is `reads` on both. The run also found a
**128-token cached floor on a cold call**. OQ-2 → not a gate on C3, a wanted input to C2. OQ-3 → a
per-tenant cache key (`cacheKey`) lands in C3, not C1, since it partitions traffic and must not
ride on C1's inertness claim. OQ-4 → auto-cache not exposed; it buys nothing once §5 does
breakpoint bookkeeping deliberately. OQ-5 → usage reporting is one stream, not split by
streaming-vs-non-streaming, to avoid reintroducing the exact "not implemented yet vs. doesn't
report" ambiguity the required `reports` discriminator exists to kill. OQ-6 → `IAiCompletionUsage`
is the token-accounting home; the sibling `ai-assist-thinking-events` stream's `thinkingTokens`
field belongs inside it, not beside it (design.md §14 A2). OQ-7 → resolved by C3, above.

**Phase A/B — the finding that shapes the whole stream.** Phase A **falsified the brief's opening
premise**: the brief claimed cache mechanism was a property of the *provider* and that OpenAI had
"nowhere to send" a directive. Wrong — OpenAI ships inline breakpoint control structurally
identical to Anthropic's (`prompt_cache_breakpoint` on a content block, `prompt_cache_options` at
request level), verified directly against `openai/openai-openapi`. What survives: the authoring
concept belongs as **stability annotation** (`frozen` / `per-conversation` / `per-request`) rather
than as a cache directive, because it is the one input that drives *all three* mechanisms (inline
breakpoint, fully automatic, and out-of-band resource).

**The central mechanical question dissolved rather than being answered.** Both breakpoint
providers cap writes at **four per request**, and the brief framed "which four survive" as the
design's core question. Phase B found the three-level vocabulary admits at most two downward
transitions, so the emitted breakpoint count is ≤2 and the shared cap of four is never
binding — OpenAI's silent drop-by-recency never engages because the design never sends more than
the cap. The cap only becomes reachable on an interleaved composition, whose real defect is its
ordering, which the diagnostics already report — so the question the brief posed does not need an
answer; it needs the case that would force one to be unreachable by construction.

### `prompt-composition-metadata` ✅ (shipped 2026-09-02 via #663 — additive)

**Status:** ✅ shipped via **#663** (authored on #661's branch, rebased onto `release` when that merged as a squash; CI green on the rebased head). Gates green — build / lint / test at **100%** in `@fgv/ts-extras` (2791 tests) and `@fgv/ts-prompt-assist` (280), repo-wide `rush rebuild` at exit 0 with **zero warnings**, change files for both verified against `origin/release`, `@fgv/testbed` (the one downstream consumer) green. **No coverage directives.** Layer-1 `code-reviewer` run on the final diff: one P1 (fixed — see below), one P2 and two P3 (all fixed).
**Package surface:** `@fgv/ts-extras` (`MustacheTemplate.renderWithSegments`, `IRenderedTemplate`, `IRenderedSegment`), `@fgv/ts-prompt-assist` (`IPromptComposition` family, opt-in on `PromptLibrary.resolve`).
**Artifacts:** `.ai/tasks/completed/2026-09/prompt-composition-metadata/`
**Origin:** the user's own question, framed explicitly as exploration — *"what would it look like to produce a metadata object along with each generated prompt indicating the order and relative size of each section"*, amended mid-turn to absolute size — then escalated to **"let's build the real thing. I usually regret shortcuts."**

**Shipped:** two surfaces answering the same question — *what is in this output, in what order, and how much of it is each part*. `renderWithSegments` returns the text `render()` produces plus a document-ordered, contiguous, gapless attribution of every code unit to literal template text or a named interpolation. `IPromptComposition` layers the anti-jailbreak preface and per-slot binding provenance on top, opt-in, with an optional caller-supplied `measure` for a second unit.

**The shortcut the user pre-empted is the whole design.** Recovering each section's offset by searching the finished text for the substituted value needs no new primitive and is a few lines. It is wrong four ways — a value used twice (reports the first occurrence for both), a value that is a substring of the literal text (`the {{w}} the` reports 0; the substitution is at 4), a value that renders empty (nothing to search for), and a value escaping alters (`<b>&</b>` appears nowhere in its 29-char escaped output). Each is now a test. What makes it worth a primitive rather than a caveat is that it fails **silently, with plausible offsets** — the worst property a diagnostic can have. Computing offsets during the render is the only sound way, and only `MustacheTemplate` owns the token list, so the work extended the sibling library rather than working around it.

**An invariant check written expecting to be unreachable fired — and the first fix for it was itself a shortcut.** `renderWithSegments` **originally** compared its accumulated text against `render()` before returning; it does not in the shipped code, and both halves of that are this paragraph. The first implementation rendered each interpolation by slicing the raw template and handing the slice back to the writer, which **re-parses it with the default delimiters** — so `A{{=<% %>=}}<%v%>B` renders `AXB` but was mapped as `A<%v%>B`. The check caught it. The first response was to **refuse** such templates, filed alongside the refusal of sections, inverted sections and partials as though the four were alike. **They are not.** A section has no correct linear map — it may repeat its body or omit it. A set-delimiter template has one; the implementation merely could not compute it. Refusing a case with a well-defined answer, because of how one chose to render, is a property of the implementation dressed up as a property of the problem. **Fixed at the cause:** each interpolation now renders from its already-parsed token via `Writer.escapedValue` / `unescapedValue` — the same primitives `render()` reaches through `renderTokens`. Delimiters are a parse-time concern, so once a token exists they are invisible, and the whole hazard class is gone rather than documented. It also stops reimplementing value semantics: dotted paths, lambdas, `null` rendering empty and non-string coercion are now delegated, verified across eleven shapes against `render()` before the change was written. `@types/mustache` types the primitives' token parameter as `string[]` while a parsed span carries numeric offsets — handled by building the `[type, name]` pair they actually read, not by casting around the typings. **And then the check itself had to go.** It was kept at first behind the stream's only `c8` directive, on the argument that it was now unreachable. A `code-reviewer` probe disproved that: the check costs a **second full render**, and mustache re-invokes a function-valued lookup every render — so it invoked a caller's lambda **twice** where `render()` invokes it once, and **failed outright** on a lambda answering differently per call, a template `render()` handles fine. Reachable from ordinary documented input; the directive's stated rationale false; and paying for the check was itself the cause of the bug. **Removed** — the identity is asserted across every shape in the test suite instead, and the package now carries **no coverage directive at all**. The margin was thin, and that is the lesson: the check had genuinely earned its keep by catching the slice-and-reparse defect, which is exactly the argument that nearly kept a real bug in the tree. **A thing that has proved useful once is not thereby correct.**

**Three uncovered branches, three different right answers, no directives.** `sec.measured ?? 0` was genuinely dead and was **removed** by accumulating the total as sections are built. `entry === undefined` on the slot lookup looked unreachable — every declared slot gets a `merged` entry, and `validateAndRender` fails the resolve for any absent variable — but `{{{.}}}` interpolates the whole render context, is never a declared slot, and no scanner rejects it; **reachable, now tested** (two earlier probes were wrong first). `winningScope === undefined` needed a scope-supplied binding the test helper could not seed; **helper extended, tested**. Asking *should this branch exist?* before *how do I cover it?* paid three times in one stream.

**A watched-it-fail run needs its own sanity check.** Eighteen neuters, applied one at a time. Three pin a fix against the code it replaced: **reinstating the slice-and-reparse** turns exactly the two set-delimiter tests red, **reinstating the self-check** turns exactly the two lambda-invocation tests red, and **reporting a zero `prefaceLength` while still prepending** turns exactly the preface test red. The first `indexOf` simulation produced **zero** red tests — a `Math.max` collapsed it back to the correct value, making the neuter a no-op. Read as "the tests do not bite", the conclusion would have been exactly backwards. Rewritten as the genuine unsound implementation, it turns exactly the four soundness tests red plus the fifth zero-length case. Two lesser notes from the same run: two neuters never reached jest because a constant condition tripped `no-constant-condition` in the build's lint pass, and the detection script initially parsed for a reporter marker Heft does not emit. **When nothing goes red, suspect the harness before the tests.**

**The router cap bit, and the stream that went over paid.** Merging #662 put `.ai/instructions/LIBRARY_CAPABILITIES.md` **91 chars over** its 18,000 cap once this stream's shortcuts joined #662's. Nothing was raised — the gate's own message says an entry that cannot be said in one line is reference material, and *"the router grew"* is explicitly not a reason to move the cap. The longest entry (safer-fetch, 225 chars) was the obvious target and the wrong one: **all six of its symbols are protected reflex anchors**, and the clause that makes it long is the security warning those anchors exist to carry. So this stream's **two** shortcuts, which asked the same question at two layers, became **one** naming both symbols — better routing than two near-duplicates, both anchors intact. Now **17,985 of 18,000 — 15 chars of headroom**, which is not comfortable: the next stream to add a shortcut must compress someone else's, and the structural fix (a larger cap, or more into per-package files) deserves a deliberate decision rather than another 15 characters.
