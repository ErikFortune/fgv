### `json-schema-fromjson-widening` ✅ (shipped 2026-10-04 via #723)

**Status: ✅ shipped via #723** into `integration/asks`. Artifacts at `.ai/tasks/completed/2026-10/json-schema-fromjson-widening/`.
*Written anticipating merge, per the artifact protocol.*

**Mission.** PersonAIlity's fgv-asks #680, #681 and #683: FastMCP (pydantic) and zod MCP servers
advertise schemas `JsonSchema.fromJson` refused, so `adaptMcpTools` skipped those tools. Widen the
subset only where the converter can enforce what the schema says and `toJson()` can say what the
converter enforces.

**What shipped.** `anyOf`/`oneOf` `[T, {type:'null'}]` normalizes to the nullable type union. Local
`$ref` (any `#/…` pointer) is resolved by inlining, so the wire stays reference-free. Recursive,
remote and anchor refs are refused, as are refs beside validation keywords and refs under or through
a nested `$id`. Inlining is bounded at 32 nested, 1000 expansions, 100000 nodes and 128 levels of depth. A new additive
`JsonSchema.record(values)` covers zod `z.record` / pydantic `dict[str, T]`, and `fromJson` reads a
schema-valued `additionalProperties` as one. Numeric `enum`, `pattern` and `{}` stay refused, the
first and last with sharper messages; all three are deferred in `docs/FUTURE.md` with their reasons.
`$dynamicRef`, `$recursiveRef` and a declared `__proto__` property were silently mishandled before
and are now refused (change file `minor`, `BREAKING:`). Outside `ts-json-base`, the only production change is that `adaptMcpTools` escapes control
characters in its skip warning; otherwise only test fixtures changed (a new adaptable pydantic-shaped
tool in `ts-extras-mcp`'s end-to-end test, refreshed mocked reasons in testbed's `mcpProbe` test).
Copilot round 3 added `undefined` refusal for records and control-character escaping of every
server-supplied string echoed in a `fromJson` failure.

**What changed shape.**
- Numeric enum and `{}` were judged by their wire, not their converter. Gemini's function-declaration
  schema allows `enum` only on strings and requires `type`, so accepting either would turn a skipped
  tool into a failing Gemini request. That needs a `ts-extras` decision; the brief makes it a
  stop-and-surface, so both were deferred instead.
- `pattern` was deferred because enforcing a server-supplied regex is a ReDoS surface. Polynomial
  backtracking defeats a syntactic safe-subset check.
- `code-reviewer` found three P1s, all fixed:
  - a record ignored `patternProperties`, `propertyNames` and `unevaluatedProperties`;
  - the expansion count bounds references, not what each inlines (the reviewer estimated about 10M
    nodes from about 230 KB), so a node budget was added;
  - `CAPABILITIES.md` was stale.
- The brief's wire citation (belief 5, `structuredOutput.ts:151`) is a comment, not a check.

**Open.** Gemini and Ollama strip a record's value schema, so the model sees an unconstrained object.
This was accepted rather than deferred: unlike numeric enum and `{}`, the request succeeds, and a
wrong value becomes a tool error the model can correct. Gate review added a 128-level depth bound,
because a 2000-deep chain exhausted the stack. A record also drops an unvalidated own `__proto__` key,
as open objects do (TECH_DEBT P3). Numeric enum and
`{}` wait on a Gemini-adapter decision in `ts-extras`. `pattern` waits on
a linear-time matcher. Declared properties plus a value schema (`.catchall()`) wait on a builder
typing. Validating keywords `fromJson` does not model (`minimum`, `const`, `prefixItems`, `patternProperties`
beside an open object, …) are accepted and ignored, a pre-existing looseness now listed in TECH_DEBT
(P3); enforcing the constraint class is #682's to fix. PersonAIlity #680 and #681 can close citing the merge commit. #683 is
partially met: record only.

### `mcp-client-cancellation` ✅ (shipped 2026-10-04 via #722)

**Status: ✅ shipped via #722** into `integration/asks`; reaches `release` with the asks batch.
Artifacts at `.ai/tasks/completed/2026-10/mcp-client-cancellation/`.
*Written anticipating merge, per the artifact protocol; the orchestrator fills in the PR number.*

**Mission.** PersonAIlity's fgv-asks #678, #673, #671 and #684. The hub raced every MCP call against
its own timeout, classified failures by checking for a `callMcpTool '` message prefix, and
reconnected on suspicion; an aborted turn left the MCP request running until the SDK's fixed 60 s.

**What shipped.** `IMcpRequestOptions` (`timeoutMs`, `signal`, `onProgress`,
`resetTimeoutOnProgress`, `maxTotalTimeoutMs`) on `callMcpTool` / `listMcpTools`, `timeoutMs` /
`signal` / `onClose` on `connectMcpSession`. Every failure carries a total `McpFailureReason` —
`tool-error`, `timeout`, `aborted`, `not-connected`, `session-expired`, `unauthorized`, `protocol`,
`transport`, `invalid-handle`, `invalid-options` — as the `DetailedResult` detail. A tool's `isError` text is still the
verbatim message. `createCustomTransport` takes any SDK transport (in-memory included).
`IAiClientTool.execute(args, context?)` receives the turn's signal, and the MCP adapter forwards it.
Proven against a real in-memory server and a loopback HTTP server; a 34-row revert matrix in
`result.md`. Change files `minor`; `ts-extras-mcp`'s is `BREAKING:`-prefixed (return types).

**What changed shape.** The SDK reports an abort with the *timeout* code, which the brief did not
know; `aborted` is decided by the identity of a per-call abort reason. The seam took the "pre-built
SDK transport" shape, against the brief's lean, because an in-memory pair would have had to name the
SDK's type. `unauthorized` shipped now (a refused static token already yields 401), so #677 adds no
kind. The catch-all is `transport`, not `unknown`. The `code-reviewer` pass moved `not-connected` from
code `-32000` (a common generic server error) to the observed close, and added schema-rejected
responses to `protocol` — whose real class name, `$ZodError`, a real-peer test caught. The gate-time
review found the SDK's `connect` awaits `transport.start()` and the `notifications/initialized` POST
outside its request options, so a server that stalled that POST hung the connect forever; the whole
connect is now raced against the abort and a deadline, proven against a real stalling HTTP server.
It also added range-validated timeouts (`invalid-options`) and single-use transport handles.
`execute` was briefly a method signature; the PR review reverted it to a property, because method
parameters are bivariant and would let a tool demand fields its schema never promises.

**Open.** The other MCP asks (#672, #674, #675, #676, #677) — what each can reuse is in `result.md`.
`maxTotalTimeoutMs` trips without a server cancellation (an SDK behaviour, documented). PersonAIlity
#678, #673, #671 and #684 can close against the merge commit.

### `json-schema-open-object` ✅ (shipped 2026-10-03 via #720)

**Status: ✅ shipped via [#720](https://github.com/ErikFortune/fgv/pull/720)**. Direct to `release`. Artifacts at `.ai/tasks/completed/2026-10/json-schema-open-object/`.
*Written anticipating merge, per the artifact protocol.*

**Mission.** PersonAIlity's fgv-ask #679. An open `JsonSchema` object (`additionalProperties: true`, or
any `fromJson` object without an explicit `false`, which is most MCP tool schemas) told the model it
was open, then converted through `Converters.object`, which keeps declared fields only. A
`dict[str, Any]` argument reached the tool as `{}`, and the call reported success.

**What shipped.** Open objects convert their declared properties as before and carry every undeclared
key through as a validated `JsonValue`; a non-object input is refused instead of becoming `{}`. The wire
schema is unchanged — it already said "open"; the converter now agrees. Additive typing:
`OpenObjectStatic<P>` and two `object()` overloads keyed on a literal `true`. Change file `minor`,
`BREAKING:`-prefixed. No consumer outside `ts-json-base` needed a test change.

**What changed shape.** The brief believed schema-valued `additionalProperties` reached the `!== false`
mapping; `fromJson` refuses it earlier. It missed a second symptom (a bare open object accepted `42`).
Two additions were built and reverted: an always-explicit `additionalProperties: true` (the requester's
proposal — Anthropic JSON outputs require `false`, and an explicit `true` was not probed), and a `Converters.jsonObject`
`__proto__` fix that defined the key as data (the second repo-wide run went red on a `ts-agent-tasks`
test that pins the key disappearing). The gate-time review's alternative shipped instead: `jsonObject`,
and an open object's top level, drop an own `__proto__` key — own keys unchanged, no prototype set, the
pin green. Closing the wire, refusing open nodes, and a "tolerate and strip"
mode were rejected (see `result.md`). An object that declares properties and omits the keyword now
keeps stray keys — the requester had called dropping them "defensible", not required.

**Open.** Schema-valued `additionalProperties` ("record") is still refused — a separate ask on
`integration/asks`; `_convertUndeclaredKeys` is its seam. Structured output does not refuse open objects on OpenAI strict (pre-existing,
`ts-extras`). Typedoc pages not regenerated, matching #655 and #659. PersonAIlity #679 can close
against the merge commit.

**What shipped.** One line in `index.browser.ts` exporting `fromBase64Strict`. Two guards: a recursive
namespace-member parity test in `ts-extras` (with a commented Node-only allowlist that is itself checked
for staleness), and a `ts-web-extras` suite that runs the crypto provider and HTTP tree against the built
browser entry. Reverting `fromBase64Strict` turns both red; reverting `deriveKeyPairFromSeed` turns the
parity test red. `ts-extras` change file `patch`, `ts-web-extras` `none`; no `.api.md` movement and no
`ts-web-extras` source change.

**What changed shape.** The brief believed `CryptoUtils.Constants` was also missing and that every AES
path threw in a browser. Running the built browser entry refuted it: `Constants` arrives through
`export * from './model'`, and an AES-GCM round trip passes with `fromBase64Strict` still removed. Only
`fromBase64Strict` was missing. Mapping the whole `ts-web-extras` suite to the browser entry was feasible
but rejected, since eight tests compare against `NodeCryptoProvider`.

**Open.** Nine other packages with a browser entry still have no parity test; the `docs/TECH_DEBT.md` P2
entry records what is now covered. The PersonAIlity ask (#648) is to be closed citing the commit.
