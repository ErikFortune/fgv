### `publish-workflow-rework` ✅ (shipped 2026-11-14 via #TBD)

**Status: ✅ shipped via #TBD** (branch `publish-workflow-rework`, based on `branch-model-plan` /
#784). Phase 0 (orchestrator) and Phase 1 of `.ai/notes/orchestrator/branch-migration-checklist.md`.
Artifacts are at `.ai/tasks/completed/2026-11/publish-workflow-rework/`.
*Written anticipating merge, per the artifact protocol.*

**Mission.** The first non-alpha publish under the new branch model (5.1.0) runs these workflows.
The stable path ran `rush publish --publish --include-all`, never wrote a CHANGELOG, and was fixed up
by hand afterwards; every action floated on a mutable tag.

**What shipped.**
- **An experiment first.** On a throwaway clone (its `origin` a scratch repo, because rush pushes
  even without `--publish`): `--include-all` ignores change files and `--apply`; `rush version
  --bump` gives 5.2.0; `rush publish --apply` breaks lockstep. Parking the policy on `5.1.0-0` and
  bumping `patch` gives 5.1.0 everywhere, populated CHANGELOGs, 771 change files consumed.
- **`publish-release-impl.yml`**, three jobs. `guard` (read-only): `publish/*` ref, branch equals
  policy, `HEAD` exactly `origin/release/<major>`, `major` ⇔ `X.0.0`, not every package already on
  npm, dist-tag `release-<n>` if older than `latest`. `build` (no npm credentials): install, version,
  commit, rebuild, **test**, tarball check, `pnpm pack` per package. `publish` (OIDC, installs
  nothing): push the bump commit first, `npm publish` each tarball, tags, a PR into
  `release/<major>`, a draft back-merge PR, a run summary. `major` reuses it;
  `publish-major-impl.yml` and the three legacy workflows are gone.
- **Alpha** keeps its semantics (package.json version as-is, `--tag alpha`, tags `<pkg>_v<V>-alpha`,
  versions on npm skipped) but now has the same guard / build / publish split.
- **`publish` trusts nothing from `build` unchecked**: the bump commit must touch only what the
  version step writes, and the tarballs must equal the guard's package list.
- **Pinning**: checkout v5.1.0 and setup-node v5.0.0 by SHA, `snow-actions` replaced by two `git
  config` lines, npm 11.21.2, dependabot `github-actions`, `contents: read` by default, and a CI step
  that fails on any unpinned `uses:`. actionlint 1.7.12 + ShellCheck: zero findings.

**What changed shape.** No single rush command publishes the version the policy already names, so
the policy is now defined as *the version to publish next*, with a branch-equals-policy guard;
after 5.1.0 a PR must move it to 5.2.0. `--override-bump major` is dropped. The draft back-merge PR
cannot be created on the very first run (`release/5` has no commits ahead of `main`); the step warns
with a compare link.

**Open.** Maintainer settings before the first dispatch (environment branch rules for `publish/*`,
"allow Actions to create pull requests", push to `publish/*`); `GITHUB_TOKEN`-opened PRs do not
trigger CI; one alpha smoke-test dispatch is recommended first. Two independent security-review rounds
(no P1s) and a second round were applied in full; their tables and the recovery procedure are in `result.md` and the
checklist.

### `luna-temperature-with-effort` ✅ (shipped 2026-11-11 via #776)

**Status: ✅ shipped via #776** into `integration/asks`, after #775. It reaches `release` with the asks

*Written anticipating merge, per the artifact protocol.*

**Mission.** A keyed `openai-model-tiers` run showed `gpt-6-luna` restricting `temperature` only while
it reasons: `0.3` with effort `'none'` accepted, `0.3` beside `low` or with no effort (default `medium`)
a 400 "Only the default (1) value is supported", `1` beside `low` accepted. ai-assist refused `1` beside
any effort as the thinking/temperature conflict, and sent `0.3` with no effort for the provider to reject.

**What shipped.**
- **Declared rule.** `IAiProviderDescriptor.samplingParamsRejectedWithThinkingModelPrefixes`, queried
  with the public `rejectsSamplingParamsWithThinking`, reusing `samplingParamsAcceptedTemperature` as the
  value accepted while reasoning. OpenAI lists `gpt-6-luna` alone; `gpt-6-sol` stays on neither list.
- **Three paths.** `checkSamplingParams` now takes the resolved thinking config on completion, streaming
  and client-tool; `temperatureAcceptedWithThinking` covers both lists so the conflict check stands aside
  for `1`. Thinking off is read from the wire the descriptor speaks (on the OpenAI format, the
  `openAiEffort ?? xaiEffort` the adapter sends), and a verbatim `'other'` block that sets the wire's
  effort key decides; no effort is the model's default, which for luna reasons. Refusal: "… does not
  accept a non-default temperature (x) while reasoning: remove temperature, send 1, or set effort
  'none'" — the last hint only where `'none'` turns thinking off. Only luna requests the provider
  would 400 change outcome (now refused locally), plus `1` beside an effort (now sent).
- **Testbed.** luna `temp=1` and `temp=1+effort=low` PASS and `temp=0.3` / `temp=0.3+effort=low` REFUSED-LOCALLY
  through the library; one raw `temp=0.3+effort=low` row is an EXPECTED-REJECT pinned to the provider's

**What changed shape.** `model.ts` crossed `max-lines`, so the sampling helpers moved to
`samplingParams.ts`. The kept raw row became a stated expected-reject rather than a report-only row.
An independent review (no P1, two P2) caught that the first cut read only typed fields, across every
provider: it refused a luna `'other'`-block `'none'` that base sent and the provider accepted, and
treated a generic `'none'` overridden by an `'other'` `low` as off. The check now follows the wire.

**Open.** `gpt-6-sol` may follow luna's rule; unlisted until a keyed run shows it. No keyed run of the

- **Alias coverage is pinned.** Every alias of every cloud provider resolves to a limit or sits on a
  commented exclusion list; an exclusion that starts resolving fails the test until removed.
