### `testbed-model-probes` ✅ (shipped 2026-11-09 via #TBD)

**Status: ✅ shipped via #TBD** into `integration/asks`. It reaches `release` with the asks batch.
Artifacts are at `.ai/tasks/completed/2026-11/testbed-model-probes/`.
*Written anticipating merge, per the artifact protocol.*

**Mission.** The user was about to run the testbed live. #765 (`resolveMaxOutputTokens`) and #767
(alias refresh) had derived several behaviours from provider docs that no live scenario exercised:
Anthropic's thinking-off handling, the temperature rules on Claude 5.x and GPT-6, and the recorded
output limits. Add a canary row for each one that states its expected outcome. No keys exist in
this environment, so the keyless path must stay STOP-FLAG.

**What shipped** (`samples/testbed` only; no `ts-extras` defect was found).
- **Anthropic thinking**: `effort=none` / `low` on every tier and extra model. `none+fail` is refused
  locally on Sonnet 5.5, Opus 5.5 and Fable 5.1 and answered on Haiku 5.5. A raw
  `thinking: {type:'disabled'}` row on each thinking-required model must be the provider's 400; if it
  answers, the listing is stale.
- **Temperature probes** with stated expectations. Anthropic must accept `1` with and without
  `'low'` and refuse `0.3` locally. On OpenAI, `gpt-6-luna` must accept `0.3` with `'none'`, and
  without it must return a provider 400 (`EXPECTED-REJECT`, #767 Q8). `gpt-6.1-sol` and
  `gpt-6-astra` must refuse it locally.
- **Max-output rows** at the recorded limit for every Anthropic, OpenAI and Gemini target.
- **New outcomes**: `REFUSED-LOCALLY`, `EXPECTED-REJECT` and `NO-RECORDED-LIMIT`. They count as
  passes, and the existing strict-none rows moved onto them.
- **The live seam is one call** over a pure, tested `buildCanaryCompletionParams`. A stubbed-`fetch`
  suite runs the real library and both real scenarios, and shows that refused rows send nothing and
  that the bodies sent match the documented wire.

**What changed shape.** The raw `disabled` row went on every thinking-required Anthropic target, not
only Sonnet 5.5, because each listing rests on its own doc quote. Per-target probes now cover extra
models for every provider, so Gemini's flash-lite gained thinking and max-output rows.

Review round 1 made `EXPECTED-REJECT` rows pass only when the provider's text matches the stated
reason, and print that text, and removed the live seam's `c8 ignore` now that stubbed runs cover it.

**Left open.** The live run itself; its run sheet is in `result.md` § 4. If Sonnet 5.5's raw row
reads "send `between_tools` instead", whether ai-assist should map `'none'` to `between_tools` there
is an ai-assist question for a later stream.

### `model-alias-refresh` ✅ (shipped 2026-11-08 via #767)

**Status: ✅ shipped via #767** into `integration/asks`. It reaches `release` with the asks batch.
Artifacts are at `.ai/tasks/completed/2026-11/model-alias-refresh/`.
*Written anticipating merge, per the artifact protocol.*

**Mission.** A user asked whether the `ai-assist` aliases were current. #765 had already noticed
drift: `@anthropic:haiku` past its target's earliest retirement date, Sonnet 5.5 listed while the
base tier named Sonnet 5, and `@openai:nano` on a deprecated snapshot. Check every alias, default and
per-model declaration against pages fetched in the run, and rotate only where the new target's wire
is confirmed.

**What shipped.**
- **Seven targets moved**, each cited in `result.md` § 1: `@anthropic:sonnet` → `claude-sonnet-5-5`,
  `@anthropic:haiku` → `claude-haiku-5-5`, `@openai:flagship` → `gpt-6.1-sol`, `@openai:nano` →
  `gpt-6-luna`, `@google-gemini:flash-image` → `gemini-nano-banana-2.1`, Groq's default →
  `openai/gpt-oss-120b` (llama-3.3-70b shut down for free and developer tiers), and Mistral's base →
  `mistral-large-4` (`mistral-large-latest` is still a name of the deprecated Large 3).
- **Wire declarations for each**: `claude-sonnet-5-5` on `anthropic-output-format` (it 400s on a
  forced `tool_choice`); `claude-haiku-5-5` in `adaptiveThinkingModelPrefixes` (it 400s on budget
  thinking, but accepts forcing, so it stays on the forced-tool catch-all); `gpt-6.1-sol` in
  `thinkingRequiredModelPrefixes` (no effort `none`); detection rules `/^claude-haiku-5-5/` and
  `/^gemini-nano-banana/`; the four new ids in the model-name unions. Each has a test.
- **Max-output coverage**: cited limits for `gpt-6.1-sol` (128000), `gemini-3.8-flash`,
  `gemini-3.5-flash-lite`, `gemini-3.1-pro-preview` and Groq's `openai/gpt-oss-120b` (65536). The
  three Gemini completion aliases left the exclusion list; xAI still states only a default and
  Mistral Large 4's page no maximum.
- **Testbed** probes follow the targets, and the canaries now exercise the forced-tool path on haiku
  and a live Gemini image, so the user's next live run verifies the rotations.

**What changed shape.**
- **Review round 1 made it more than a currency pass.** It found that a generic `effort: 'none'`
  never turned thinking off on an Anthropic adaptive model (omitting `thinking` leaves it on), and
  that the rotations turned `temperature` into a provider 400 on more targets. Now `'none'` sends
  `thinking: {type: 'disabled'}` to `claude-sonnet-5`, `claude-opus-5` and `claude-haiku-5-5`, and
  Opus 5.5, Sonnet 5.5, Fable and Mythos join `thinkingRequiredModelPrefixes` (`'none'` → `'low'`);
  `claude-mythos-5` became adaptive. A new `samplingParamsRejectedModelPrefixes` /
  `rejectsSamplingParams` refuses `temperature` up front — on Anthropic (every Claude 5.x model,
  Mythos Preview, Opus 4.7/4.8) only a non-default value, since `samplingParamsAcceptedTemperature: 1`
  lets the provider's default through; on `gpt-6-astra` and `gpt-6.1-sol` any value. Round 2 also
  made Opus 4.7/4.8 adaptive (a budget 400s on both) and made the client-tool path refuse a
  caller-built thinking-off flag for a model that cannot run with thinking off. Every
  consumer-visible change is listed in the change file.
- **Three rotations held**: Gemini 4 Argon is Google's Stable flagship, but it requires
  `thinkingLevel` and deprecates the `thinkingBudget` ai-assist sends, so `@google-gemini:pro` stays
  on the 3.1 Pro preview; `gpt-image-2.6-sunburst` is not clearly a successor (2.5 is still badged
  "Default"); `gemini-embedding-2` would change vector space under existing indexes.
- Behaviour moves under consumers who use aliases: Anthropic's base tier structured output changes
  wire, OpenAI's advanced tier can no longer run with thinking off, and `@openai:nano` now equals
  `@openai:mini`.

**Left open** (`state.md` Q2–Q8; Q1 decided: `@openai:nano` stays).
- `gpt-6-luna` / `gpt-6-sol` reject `temperature` unless effort is `'none'` — effort-conditional, so
  disclosed rather than guarded; it now reaches `@openai:nano`.
- A `thinkingLevel` wire for Gemini 3/4 — the prerequisite for moving `@google-gemini:pro` to Argon.
- Whether `gpt-image-2.6-sunburst` takes the image role; whether to adopt `gemini-embedding-2`.
- Groq marks `max_tokens` deprecated in favour of `max_completion_tokens`; ai-assist still sends
  `max_tokens` to every OpenAI-format provider except OpenAI.

### `model-max-output-tokens` ✅ (shipped 2026-11-08 via #765)

**Status: ✅ shipped via #765** into `integration/asks`. It reaches `release` with the asks batch.
Artifacts are at `.ai/tasks/completed/2026-11/model-max-output-tokens/`.
*Written anticipating merge, per the artifact protocol.*

**Mission.** personaility#724 (fgv-ask). Anthropic and OpenAI refuse a `maxTokens` above a model's
output limit. Aliases resolve inside fgv, so a consumer cannot know which model a slot reaches and
had to pick one number for all of them — too large for a mini-tier model if it leaves room for an
always-thinking Claude's reasoning. Give them the lookup so they can cap at
`min(their cap, model limit)`.

**What shipped.**
- **`resolveMaxOutputTokens(descriptor, modelOverride?, context?): number | undefined`**, taking the
  same `ModelSpec` and tier as `resolveProviderModel` and resolving through it, so a consumer passes
  what the completion call gets. With `IAiMaxOutputTokensCapability { modelId, maxOutputTokens }`
  and the optional descriptor field `maxOutputTokens`. `undefined` when no model resolves, the
  provider has no entries, or no entry names the model.
- **Exact ids, cited values.** An entry matches only the concrete id it names — no prefix, no
  snapshot suffix. Anthropic: 128000 for `claude-opus-5-5`, `-opus-5`, `-sonnet-5-5`, `-sonnet-5`,
  `-fable-5-1`, `-fable-5`, `-mythos-5-1`, `-mythos-5`, `-haiku-5-5`; 64000 for `claude-haiku-4-5`
  and its named snapshot `claude-haiku-4-5-20251001`. OpenAI: 128000 for `gpt-6-luna`, `gpt-6-sol`,
  `gpt-6-astra`, `gpt-5.4-nano` and its named snapshot `gpt-5.4-nano-2026-03-17`. The citations table quotes each page.
- **Alias coverage is pinned.** Every alias of every cloud provider resolves to a limit or sits on a
  commented exclusion list; an exclusion that starts resolving fails the test until removed.
- **Explicit `maxTokens` is never clamped** — the consumer decides; a silent clamp would trade a loud
  refusal for silent truncation.
- **`DEFAULT_ANTHROPIC_MAX_TOKENS` (4096) is below every recorded limit**, so no adapter changed. A
  test pins the finding and was watched going red against a lowered limit.

**What changed shape.**
- **Review amended the brief three times.** Longest-prefix matching (the sibling capabilities'
  idiom, as briefed) gave uncited limits to `claude-opus-5-6`, `gpt-6-luna-mini` and similar ids;
  the dated-snapshot rule that replaced it did the same for snapshots no page names, so matching is
  now exact id only. And the lookup took only a string, so a consumer holding a `ModelSpec` and a
  tier had no path; it now takes `resolveProviderModel`'s arguments.
- The brief asked for every cloud provider. Gemini, Groq and Mistral docs hosts were outside the
  session's network, and xAI documents only a 128,000 *default*, not a maximum, so those record
  nothing and return `undefined`.
- Anthropic's pages say "128K" without an integer; recorded as 128000 on the docs' own use of `k`.

**Left open.**
- Fill Gemini, Groq and Mistral from their docs pages, and xAI if it publishes a maximum.
- `resolveModel` throws on a `ModelSpec` outside its type; filed in `docs/TECH_DEBT.md` (P3).
- `@anthropic:haiku` still names Haiku 4.5, a legacy model past its earliest retirement date, and
  OpenAI's page marks the `gpt-5.4-nano` snapshot deprecated. Alias rotation was out of scope.
