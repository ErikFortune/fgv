### `deps-refresh` ✅ (shipped 2026-11-08 via #TBD)

**Status: ✅ shipped via #TBD** into `integration/asks`. It reaches `release` with the asks batch.
Artifacts are at `.ai/tasks/completed/2026-11/deps-refresh/`.
*Written anticipating merge, per the artifact protocol.*

**Mission.** A user request: the dependencies had not been refreshed in a while and Dependabot was
flagging the repo. Audit first, fix what has a fix inside the current majors, take every minor and
patch, report the majors.

**What shipped.**
- **Rush lockfile audit 173 → 3.** In `common/config/rush/pnpm-lock.yaml`, 4 critical / 73 high /
  84 moderate / 12 low became 0 / 0 / 2 / 1. What is left: `glob` and `minimatch` (moderate; the
  fix is a major of a transitive whose parents, jest, typescript-eslint and api-extractor, do not
  range it, and every pattern is repo-authored) and `deepmerge` (low; no fix published).
  `elliptic` closed when the unused `crypto-browserify` was removed from two tools.
- **The other lockfiles are not all clean.** The root `package-lock.json`, which is what
  Dependabot scans, went from 11 high / 6 moderate / 2 low to **1 high** / 1 moderate. Root
  `@microsoft/rush` was raised to `^5.182.1` and the lock regenerated with npm, an
  orchestrator-approved exception to the never-npm rule. The high left is `@azure/msal-node`: Rush's
  Azure build-cache plugin pins `@azure/identity ~4.13.1`, so the fix needs a major below Rush, and
  this repo's cache provider is `local-only`. The `rush-pack-check` autoinstaller lost its two highs;
  `rush-prettier` and `rush-bundler-check` had none. Before and after tables for every lockfile are
  in `result.md` § 2.
- **Rush 5.177.2 → 5.182.1, pnpm 11.12.0 → 11.28.9**, one `rush update --full` (which alone
  closed most of the list — the vulnerable versions were lockfile pins below what their parents
  already allowed), six direct security bumps (`hono`, `js-yaml`, `@huggingface/transformers`,
  and raised floors for `@modelcontextprotocol/sdk`, `axios`, `react-router-dom`), and two scoped
  overrides: `css-minimizer-webpack-plugin>serialize-javascript ^7.1.4`, `sockjs>uuid ^11.1.1`.
- **`@types/node` to 22.x**, the oldest runtime `rush.json` supports (`>=22.22.0 <23 || >=24.15.0
  <25`); MONOREPO_GUIDE's stale "Node 20 / pnpm 8" runtime line was corrected to match.
- **58 more direct ranges** moved to the latest release in their major that was at least two days
  old. 22 `patch` change files, 13 `none`.
- **One forced source change.** `@modelcontextprotocol/sdk` 1.32 defaults to following only
  same-origin redirects, and `ts-extras-mcp`'s egress test had a control asserting the platform
  followed a cross-origin one. `rush rebuild` was clean; only the repo-wide `rush test` caught it.
  The control, the TSDoc and the README now describe the SDK's default. Because the SDK now refuses
  the cross-origin hop itself, that test no longer exercised the package's own `redirect: 'error'`.
  A new same-origin 307 test does: it went red with that line reverted and green with it restored. The two webauthn `api.md` reports also re-render their
  re-exported types through aliases.

**What changed shape.**
- **`globalOverrides` had been silently ignored.** Rush 5.177.2 wrote overrides to
  `common/temp/package.json`'s `pnpm` field, which pnpm 11 does not read; 5.178.0 moved them to
  `pnpm-workspace.yaml`. The Rush bump became a precondition rather than a refresh.
- **The Heft toolchain family is held at its current pins.** Taken, it failed `rush rebuild`:
  `heft-lint-plugin` 1.3 lints files outside the TypeScript program, which turns the
  `eslint.config.js` override blocks that name a packlets rule without a `files` glob (36 files set
  that rule) into config errors, and `@rushstack/eslint-config` 4.9 warns
  on every `private _member`. The plugins pin `@rushstack/heft` exactly, so the family moves
  together or not at all. `@rushstack/eslint-config` moved only to 4.7.0, the version the rigs
  already ran.
- **Two in-major bumps held by package policy:** `re2js` (each bump reviewed against the dialect
  table; the upstream changelog was unreachable here) and `@typesafe-ai/sdk` (a 0.x minor is a
  wire change). `@testing-library/jest-dom` pinned to `~6.9.1` because 6.10.0 is a deprecated
  breaking release.

**Left open.**
- The majors list in `result.md` § 4d — 22 rows with effort — is the user's follow-up decision.
  The two that gate others: the Heft family / eslint-config 4.9 private-members decision (L), which
  `eslint` 10 waits on (now a P2 in `docs/TECH_DEBT.md`). The Node floor (22.22 / 24.15) blocks none
  of them.
- `@azure/msal-node` (high) in the root lockfile, until Rush moves its `@azure/identity` pin.
- `re2js` 2.9.1 awaits its dialect-table review.

### `model-max-output-tokens` ✅ (shipped 2026-11-08 via #765)

**Status: ✅ shipped via #765** into `integration/asks`. It reaches `release` with the asks batch.
Artifacts are at `.ai/tasks/completed/2026-11/model-max-output-tokens/`.
*Written anticipating merge, per the artifact protocol.*

**Mission.** personaility#724 (fgv-ask). Anthropic and OpenAI refuse a `maxTokens` above a model's
output limit. Aliases resolve inside fgv, so a consumer cannot know which model a slot reaches and
had to pick one number for all of them — too large for a mini-tier model if it leaves room for an
always-thinking Claude's reasoning. Give them the lookup so they can cap at
`min(their cap, model limit)`.

**What shipped.**
- **`resolveMaxOutputTokens(descriptor, modelOverride?, context?): number | undefined`**, taking the
  same `ModelSpec` and tier as `resolveProviderModel` and resolving through it, so a consumer passes
  what the completion call gets. With `IAiMaxOutputTokensCapability { modelId, maxOutputTokens }`
  and the optional descriptor field `maxOutputTokens`. `undefined` when no model resolves, the
  provider has no entries, or no entry names the model.
- **Exact ids, cited values.** An entry matches only the concrete id it names — no prefix, no
  snapshot suffix. Anthropic: 128000 for `claude-opus-5-5`, `-opus-5`, `-sonnet-5-5`, `-sonnet-5`,
  `-fable-5-1`, `-fable-5`, `-mythos-5-1`, `-mythos-5`, `-haiku-5-5`; 64000 for `claude-haiku-4-5`
  and its named snapshot `claude-haiku-4-5-20251001`. OpenAI: 128000 for `gpt-6-luna`, `gpt-6-sol`,
  `gpt-6-astra`, `gpt-5.4-nano` and its named snapshot `gpt-5.4-nano-2026-03-17`. The citations table quotes each page.
- **Alias coverage is pinned.** Every alias of every cloud provider resolves to a limit or sits on a
  commented exclusion list; an exclusion that starts resolving fails the test until removed.
- **Explicit `maxTokens` is never clamped** — the consumer decides; a silent clamp would trade a loud
  refusal for silent truncation.
- **`DEFAULT_ANTHROPIC_MAX_TOKENS` (4096) is below every recorded limit**, so no adapter changed. A
  test pins the finding and was watched going red against a lowered limit.

**What changed shape.**
- **Review amended the brief three times.** Longest-prefix matching (the sibling capabilities'
  idiom, as briefed) gave uncited limits to `claude-opus-5-6`, `gpt-6-luna-mini` and similar ids;
  the dated-snapshot rule that replaced it did the same for snapshots no page names, so matching is
  now exact id only. And the lookup took only a string, so a consumer holding a `ModelSpec` and a
  tier had no path; it now takes `resolveProviderModel`'s arguments.
- The brief asked for every cloud provider. Gemini, Groq and Mistral docs hosts were outside the
  session's network, and xAI documents only a 128,000 *default*, not a maximum, so those record
  nothing and return `undefined`.
- Anthropic's pages say "128K" without an integer; recorded as 128000 on the docs' own use of `k`.

**Left open.**
- Fill Gemini, Groq and Mistral from their docs pages, and xAI if it publishes a maximum.
- `resolveModel` throws on a `ModelSpec` outside its type; filed in `docs/TECH_DEBT.md` (P3).
- `@anthropic:haiku` still names Haiku 4.5, a legacy model past its earliest retirement date, and
  OpenAI's page marks the `gpt-5.4-nano` snapshot deprecated. Alias rotation was out of scope.
