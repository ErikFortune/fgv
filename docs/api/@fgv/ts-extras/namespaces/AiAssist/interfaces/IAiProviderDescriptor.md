# Interface: IAiProviderDescriptor

Describes a single AI provider — single source of truth for all metadata.

## Properties

| Property | Modifier | Type | Description |
| ------ | ------ | ------ | ------ |
| <a id="property-acceptsimageinput"></a> `acceptsImageInput` | `readonly` | `boolean` | Whether this provider's chat completions API accepts image input (i.e. supports vision prompts). When false, calls with `prompt.attachments` are rejected up front. |
| <a id="property-adaptivethinkingmodelprefixes"></a> `adaptiveThinkingModelPrefixes?` | `readonly` | readonly `string`[] | Concrete Anthropic model ids (exact-or-dash-bounded-prefix-matched) that require the adaptive thinking wire shape (`thinking: { type: 'adaptive' }` + top-level `output_config: { effort }`) rather than the legacy manual-budget shape (`thinking: { type: 'enabled', budget_tokens }`). Non-Anthropic `apiFormat`s ignore this. **Remarks** The Claude 5 family (`claude-sonnet-5`, `claude-opus-5`, `claude-fable-5`, including their dated snapshots) rejects `thinking.type: 'enabled'` with an HTTP 400 and requires the adaptive shape; older models (`claude-sonnet-4-6`, `claude-opus-4-8`, `claude-haiku-4-5`, etc.) keep the legacy shape. The completion (`callProviderCompletion`), streaming (`callProviderCompletionStream`), and client-tool (`executeClientToolTurn`) Anthropic dispatch sites consult this list (via the sibling predicate `isAdaptiveThinkingModel`) to pick the correct wire shape for the resolved model. Mirrors the prefix-matching shape of `responsesOnlyModelPrefixes`, but with exact-or-dash-bounded matching (an entry matches a resolved model that equals it or starts with it followed by `-`) rather than a plain prefix, since Anthropic model families share numeric leading characters (`claude-sonnet-5` vs. a hypothetical `claude-sonnet-50`). Empty or undefined means no model uses the adaptive shape. |
| <a id="property-aliases"></a> `aliases?` | `readonly` | [`IModelAliasMap`](IModelAliasMap.md) | Canonical fgv alias → concrete model map for this provider. Absent means the provider defines no aliases and every model string passes through verbatim. **Remarks** Keys are full fgv aliases (`@<providerId>:<role>`); values are the current concrete model id (or a provider-native alias). Consulted by [resolveModelAlias](../functions/resolveModelAlias.md) / [resolveProviderModel](../functions/resolveProviderModel.md) at each call-time resolution chokepoint, downstream of the [ModelSpecKey](../type-aliases/ModelSpecKey.md) walk. Additive and optional — composes with the existing per-descriptor `imageGeneration` / `embedding` capability arrays. |
| <a id="property-anthropicthinkingofftypes"></a> `anthropicThinkingOffTypes?` | `readonly` | readonly [`IAnthropicThinkingOffRule`](IAnthropicThinkingOffRule.md)[] | Per-model Anthropic thinking-off values for adaptive-thinking models that turn thinking off with something other than `thinking: { type: 'disabled' }`, the default. Each rule's `modelPrefix` is matched exact-or-dash-bounded, like [IAiProviderDescriptor.adaptiveThinkingModelPrefixes](#property-adaptivethinkingmodelprefixes); the first match wins. Like those lists, a rule deliberately also matches future variants of its id (`claude-sonnet-5-5-<date>`). **Remarks** Read by the completion, streaming and client-tool Anthropic emit sites (via [AiAssist.resolveAnthropicThinkingOffType](../functions/resolveAnthropicThinkingOffType.md)) when a generic `effort: 'none'` (or a caller-built `anthropicThinkingDisabled` flag) turns thinking off on an adaptive model. Empty or undefined means every model uses `'disabled'`. |
| <a id="property-apiformat"></a> `apiFormat` | `readonly` | [`AiApiFormat`](../type-aliases/AiApiFormat.md) | Which API adapter format to use |
| <a id="property-baseurl"></a> `baseUrl` | `readonly` | `string` | Base URL for the API (e.g. 'https://api.x.ai/v1') |
| <a id="property-buttonlabel"></a> `buttonLabel` | `readonly` | `string` | Button label for action buttons (e.g. "AI Assist \| Grok") |
| <a id="property-chatoutputtokensfield"></a> `chatOutputTokensField?` | `readonly` | [`ChatOutputTokensField`](../type-aliases/ChatOutputTokensField.md) | The Chat Completions request field that carries `maxTokens` on this provider's OpenAI-format chat path: `'max_completion_tokens'`, or the legacy `'max_tokens'` (the default when undefined). Declare `'max_completion_tokens'` only where the provider's API reference accepts it; a server that does not know the field ignores it and the cap is lost. Read through [AiAssist.usesMaxCompletionTokensField](../functions/usesMaxCompletionTokensField.md). Not consulted on the Responses API path (`max_output_tokens`) or by a non-`'openai'` `apiFormat`. |
| <a id="property-corsrestricted"></a> `corsRestricted` | `readonly` | `boolean` | Whether this provider's API enforces CORS restrictions that prevent direct browser calls. |
| <a id="property-defaultmodel"></a> `defaultModel` | `readonly` | [`ModelSpec`](../type-aliases/ModelSpec.md) | Default model specification — string or context-aware map. |
| <a id="property-embedding"></a> `embedding?` | `readonly` | readonly [`IAiEmbeddingModelCapability`](IAiEmbeddingModelCapability.md)[] | Embedding capabilities, scoped to model id prefixes. Empty or undefined means the provider does not support embeddings. **Remarks** The dispatcher matches the resolved embedding model id against each rule's `modelPrefix` and selects the longest match (see [AiAssist.resolveEmbeddingCapability](../functions/resolveEmbeddingCapability.md)). An empty `modelPrefix` is the catch-all and matches every model id. Embedding-model selection uses the `embedding` [ModelSpecKey](../type-aliases/ModelSpecKey.md). Providers that declare `embedding` should declare a model in `defaultModel.embedding`, e.g. `{ base: '@openai:mini', embedding: '@openai:embedding' }`. Self-hosted providers (`ollama`, `openai-compat`) leave it unset — the caller supplies the embedding model via `modelOverride`. |
| <a id="property-geminithinkinglevelrejectedmodelprefixes"></a> `geminiThinkingLevelRejectedModelPrefixes?` | `readonly` | readonly `string`[] | Gemini models (exact-or-dash-bounded) that do not support `thinkingLevel` at all and take only `thinkingBudget`. An explicit `thinkingLevel` aimed at one — in a `google` block, or in a caller-built `resolvedThinking` on `executeClientToolTurn` — is refused before the wire (see [AiAssist.rejectsGeminiThinkingLevel](../functions/rejectsGeminiThinkingLevel.md)). Models on neither this list nor [AiAssist.IAiProviderDescriptor.geminiThinkingLevels](#property-geminithinkinglevels) are sent an explicit level verbatim. |
| <a id="property-geminithinkinglevels"></a> `geminiThinkingLevels?` | `readonly` | readonly [`IGeminiThinkingLevelRule`](IGeminiThinkingLevelRule.md)[] | Gemini models sent `thinkingLevel` rather than `thinkingBudget`, each with the levels it accepts, lowest first; matched exact-or-dash-bounded, longest prefix wins (see [AiAssist.resolveGeminiThinkingLevels](../functions/resolveGeminiThinkingLevels.md)). On a matching model a generic `'none'` is sent as `'minimal'` where listed (otherwise handled like a thinking-required model, or refused), other efforts map 1:1 or are refused when unlisted. Unmatched models keep the budget wire. |
| <a id="property-id"></a> `id` | `readonly` | [`AiProviderId`](../type-aliases/AiProviderId.md) | Provider identifier (e.g. 'xai-grok', 'anthropic') |
| <a id="property-imagegeneration"></a> `imageGeneration?` | `readonly` | readonly [`IAiImageModelCapability`](IAiImageModelCapability.md)[] | Image-generation capabilities, scoped to model id prefixes. Empty or undefined means the provider does not support image generation. **Remarks** The dispatcher matches the resolved model id against each rule's `modelPrefix` and selects the longest match (see [AiAssist.resolveImageCapability](../functions/resolveImageCapability.md)). An empty `modelPrefix` is the catch-all and matches every model id. Multiple entries support providers that host more than one image-API surface under one baseUrl. The dispatcher selects the longest-matching prefix, so a provider can list a specific-prefix surface alongside an empty-prefix catch-all and the right model routes to the right API. Image-model selection reuses the existing `image` [ModelSpecKey](../type-aliases/ModelSpecKey.md). Providers that declare `imageGeneration` should declare a model in `defaultModel.image`, e.g. `{ base: '@openai:mini', image: '@openai:image' }`. |
| <a id="property-label"></a> `label` | `readonly` | `string` | Human-readable label (e.g. "xAI Grok") |
| <a id="property-maxoutputtokens"></a> `maxOutputTokens?` | `readonly` | readonly [`IAiMaxOutputTokensCapability`](IAiMaxOutputTokensCapability.md)[] | Per-model maximum output tokens — the largest `maxTokens` the provider accepts for a completion on that model. Absent (or no matching entry) means the limit is unknown. **Remarks** Read through [AiAssist.resolveMaxOutputTokens](../functions/resolveMaxOutputTokens.md), which resolves the model the same way a completion call does (the `ModelSpec` walk, then aliases) before matching. Unlike `imageGeneration`, `embedding` and `structuredOutput`, entries are **not** prefix-matched. An output limit is a fact about one model, and the sibling a prefix would also catch (a `-mini` or `-nano` variant, a later point release) is exactly where the limit changes, and a dated snapshot is a separate model id. An entry applies only to the model whose resolved id equals its `modelId`. A wrong number is worse than none: a value above the real limit is refused by Anthropic and OpenAI, and a value below it silently truncates. Each value is the limit a request **as ai-assist sends it** gets: a higher limit available only behind an opt-in beta header or a batch endpoint that ai-assist does not use is not recorded. |
| <a id="property-needssecret"></a> `needsSecret` | `readonly` | `boolean` | Whether this provider requires an API key secret |
| <a id="property-responsesonlymodelprefixes"></a> `responsesOnlyModelPrefixes?` | `readonly` | readonly `string`[] | Concrete model ids (prefix-matched) that must be invoked via the OpenAI Responses API rather than chat completions — e.g. `gpt-5.5-pro`. Non-OpenAI `apiFormat`s ignore this. **Remarks** Some current-generation OpenAI models (the `-pro` tier) are Responses-API-only and 400 on `/chat/completions`. The completion and streaming dispatch consult this list (via the sibling predicate [AiAssist.isResponsesOnlyModel](../functions/isResponsesOnlyModel.md)) and route a matching model to the Responses path even when no tools are requested. Mirrors the prefix-matching shape of the `imageGeneration` / `embedding` capability arrays; adding a new Responses-only line is a one-entry descriptor edit. Empty or undefined means no model is Responses-only. |
| <a id="property-samplingparamsacceptedtemperature"></a> `samplingParamsAcceptedTemperature?` | `readonly` | `number` | The one `temperature` that the models on [IAiProviderDescriptor.samplingParamsRejectedModelPrefixes](#property-samplingparamsrejectedmodelprefixes) still accept, with or without thinking, and that the models on [IAiProviderDescriptor.samplingParamsRejectedWithThinkingModelPrefixes](#property-samplingparamsrejectedwiththinkingmodelprefixes) still accept while reasoning — the provider's own default, which a provider that rejects only non-default values lets through. Undefined means those models accept no `temperature` where they restrict it. Descriptor-wide, not per model: declare it only when the evidence covers every listed model (OpenAI lists `gpt-6.1-sol` and `gpt-6-astra` on the first list and `gpt-6-luna` on the second, and all three accepted `temperature: 1` live with thinking on). |
| <a id="property-samplingparamsrejectedmodelprefixes"></a> `samplingParamsRejectedModelPrefixes?` | `readonly` | readonly `string`[] | Concrete model ids (exact-or-dash-bounded-prefix-matched, like [IAiProviderDescriptor.thinkingRequiredModelPrefixes](#property-thinkingrequiredmodelprefixes)) that reject a caller-supplied `temperature` with or without thinking — every value, or every value but [IAiProviderDescriptor.samplingParamsAcceptedTemperature](#property-samplingparamsacceptedtemperature) when the descriptor declares one. A call that sets a rejected `temperature` on a listed model is refused before the wire (see [AiAssist.rejectsSamplingParams](../functions/rejectsSamplingParams.md)). Empty or undefined means every model accepts `temperature` (subject to the thinking-mode conflict). |
| <a id="property-samplingparamsrejectedwiththinkingmodelprefixes"></a> `samplingParamsRejectedWithThinkingModelPrefixes?` | `readonly` | readonly `string`[] | Concrete model ids (exact-or-dash-bounded-prefix-matched, like [IAiProviderDescriptor.samplingParamsRejectedModelPrefixes](#property-samplingparamsrejectedmodelprefixes)) that reason by default and reject a caller-supplied `temperature` only while reasoning — every value, or every value but [IAiProviderDescriptor.samplingParamsAcceptedTemperature](#property-samplingparamsacceptedtemperature) when the descriptor declares one. With thinking off they accept any `temperature`. **Remarks** Thinking counts as off when the request sends the descriptor's wire format its off value: on the OpenAI format an effort of `'none'`, on Anthropic thinking disabled, on Gemini a budget of `0`. A verbatim `'other'` block that sets the wire's effort key decides, since it is merged last; otherwise the typed effort does. A request with no effort runs at the model's default, which for a listed model reasons. A generic `effort: 'none'` turns thinking off only where it is sent as off — not on a thinking-required model, which degrades it, nor on a Gemini level model, which sends a level. A rejected `temperature` on a listed model is refused before the wire on the completion, streaming and client-tool paths (see [AiAssist.rejectsSamplingParamsWithThinking](../functions/rejectsSamplingParamsWithThinking.md)). A model on both lists follows [IAiProviderDescriptor.samplingParamsRejectedModelPrefixes](#property-samplingparamsrejectedmodelprefixes). |
| <a id="property-servertoolsexclusivewithclienttools"></a> `serverToolsExclusiveWithClientTools?` | `readonly` | readonly `"web_search"`[] | Server tools this provider's API refuses to accept in the *same request* as client (function) tools. Absent or empty means the provider imposes no such constraint and any supported server tool may be mixed with client tools. **Remarks** This is a narrower statement than [AiAssist.IAiProviderDescriptor.supportedTools](#property-supportedtools): a tool listed here is genuinely supported, just not *together* with function calling. Only Gemini declares anything today — its `generateContent` API HTTP-400s (`INVALID_ARGUMENT`) when built-in grounding (`web_search` → `google_search`) and `function_declarations` appear in one request. Declaring the rule here rather than enforcing it at the call site is the point: [AiAssist.resolveToolConflicts](../functions/resolveToolConflicts.md) applies it generically, so a host never writes `if (descriptor.apiFormat === 'gemini')` in its tool assembly, and the day a provider lifts its limit only this line changes. Optional because most providers have nothing to say. The library's own registry descriptors are the ones that reach the wire and are pinned by test; a hand-built descriptor that omits this simply gets the unconstrained behavior, which is the correct reading of "declares no constraint". |
| <a id="property-streamingcorsrestricted"></a> `streamingCorsRestricted` | `readonly` | `boolean` | Whether this provider's streaming completion endpoint requires a proxy for direct browser calls. Some providers gate streaming separately from non-streaming (rare), so this is tracked independently from [IAiProviderDescriptor.corsRestricted](#property-corsrestricted). **Remarks** When `true`, `callProviderCompletionStream` rejects up front unless the call is being routed through a proxy. |
| <a id="property-structuredoutput"></a> `structuredOutput?` | `readonly` | readonly [`IAiStructuredOutputCapability`](IAiStructuredOutputCapability.md)[] | Per-model-family structured-output capability, longest-prefix matched against the **resolved** completion model id. Absent (or no matching entry) means the model can enforce nothing, and a request against it reports `'none'`. **Remarks** Same declaration idiom as `imageGeneration` and `embedding`, resolved through the same alias-first helper — a capability lookup on an unresolved alias is the defect `resolveImageCapability` once had, where a catch-all `modelPrefix: ''` turned an unknown alias into a confidently wrong answer. Note this declares which wire format a model *family* supports, not which OpenAI endpoint a given call will take — that also depends on whether the call carries server tools, so the dispatcher supplies it. |
| <a id="property-supportedtools"></a> `supportedTools` | `readonly` | readonly `"web_search"`[] | Which server-side tools this provider supports (empty = none). |
| <a id="property-thinkingrequiredmodelprefixes"></a> `thinkingRequiredModelPrefixes?` | `readonly` | readonly `string`[] | Concrete model ids (exact-or-dash-bounded-prefix-matched, like [IAiProviderDescriptor.adaptiveThinkingModelPrefixes](#property-adaptivethinkingmodelprefixes)) that cannot run with thinking off. The provider rejects the off value ai-assist would send for a generic `effort: 'none'`: `reasoning_effort: 'none'` (OpenAI, xAI), `thinkingBudget: 0` (Gemini on the budget wire; on the level wire, a model with no `'minimal'` level — see [AiAssist.IAiProviderDescriptor.geminiThinkingLevels](#property-geminithinkinglevels)), or the model's off `thinking` value (Anthropic adaptive-thinking models; see [IAiProviderDescriptor.anthropicThinkingOffTypes](#property-anthropicthinkingofftypes)). A model that accepts the off value but ignores it, still thinking, is listed too, so that `'none'` never claims an effect it lacks. **Remarks** A generic `'none'` on a listed model is handled by [IThinkingConfig.onUnsupported](IThinkingConfig.md#property-onunsupported). It is sent as `'low'` by default, or refused before the wire. Provider-specific blocks in [IThinkingConfig.providers](IThinkingConfig.md#property-providers) are sent verbatim and are not checked, and the `'none'` handling stands aside entirely when an applicable block sets the provider's effort (a typed block's `effort`, `thinkingBudget` or `thinkingLevel`, or an `'other'` block's wire field). Empty or undefined means every model accepts `'none'`. |
