## Fix 1 — restore `BrowserHashProvider` at the root of `@fgv/ts-web-extras`

- On `main`, `libraries/ts-web-extras/src/index.ts` did `export * from './packlets/crypto'`, so
  `BrowserHashProvider` was a root export (`etc/ts-web-extras.api.md` on main, line 11).
- #652 (0765a2068) moved it under the `CryptoUtils` namespace (`import * as CryptoUtils from
  './packlets/crypto-utils'`) and no change file recorded the removal.
- Restore the root export **in addition to** `CryptoUtils.BrowserHashProvider` (same class, not a
  copy): an `export { BrowserHashProvider } from './packlets/crypto-utils';` line in the library
  barrel `src/index.ts` (a barrel is the sanctioned place for re-exports). Do not remove the
  namespace form.
- Then diff the **whole** root surface of `ts-web-extras` on main against this branch
  (`etc/ts-web-extras.api.md`): every name exported at the root on main must still be exported at
  the root with a compatible shape. If anything other than `BrowserHashProvider` is missing,
  restore it the same way and record it. (The audit also found `FileApiTreeAccessors` dropped an
  unused class type parameter; leave that — it is documented in the release notes instead.)
- Add a test asserting the root export exists and is the identical class
  (`toBe(CryptoUtils.BrowserHashProvider)`), and that it works (hash a short string).
- Regenerate `etc/ts-web-extras.api.md`.
- Change file `@fgv/ts-web-extras`, type `patch`: "Restore the root `BrowserHashProvider` export
  that 5.0.2 had; it is also available as `CryptoUtils.BrowserHashProvider`."

## Fix 2 — relax `engines.node` on two tools

- `tools/ts-res-browser/package.json` and `tools/ts-res-browser-cli/package.json` publish
  `"node": ">=22.22.0 <23.0.0 || >=24.15.0 <25.0.0"`, which excludes Node 23, 25 and 26 that the
  5.0.2 range (`>=20.0.0`) accepted. Set both to `">=22.22.0"`. (Node 20 is end-of-life; dropping
  it stays.) Check every other published package's `engines` the same way and report any other
  upper bound; change only these two unless you find the same defect elsewhere, in which case fix
  it identically and record it.
- This is a manifest field, not a dependency: edit `package.json` directly is correct here.
  No lockfile change is expected; if `rush install` wants one, record why.
- Change files for each tool, type `patch`: "Accept any Node from 22.22.0 up; the published range
  no longer excludes Node 23 and later."
