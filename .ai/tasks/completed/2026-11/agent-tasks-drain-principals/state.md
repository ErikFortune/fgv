## Decisions as built

1. **Drain principals at `subscribe`** — `ISubscribeRequest.drainPrincipals`. Converted by
   `drainPrincipalsRequest` (bounded at `maxDrainPrincipals` = 32, non-empty, each a principal key,
   de-duplicated and sorted); stored strictly (`drainPrincipals`: non-empty, unique, ascending).
   **Placed in `ITaskSubscriptionSpecification`** (optional there, so a legacy record still
   converts), which means it is in the pending manifest entry, the first record (`...specification`),
   the live-replay comparison and the pending-resume identity without separate plumbing.
   `ITaskSubscription.drainPrincipals` is required and always the rule applied (legacy resolved).
   *Refinement:* when a list is given the registrant is **not** added implicitly — "default when
   omitted: the registering principal only" reads as exactly that, and a host that names only the
   agent should not keep a host binding able to drain.
2. **`bindDelivery`** refuses a non-drain principal with the same message and detail as a missing
   subscription / wrong consumer (test pins all three equal). **Refinement:** every bound-delivery
   operation re-applies the rule to the subscription as it stands, so a long-lived binding (the pump)
   is not grandfathered after the host removes its principal. See the window table in `result.md`.
3. **Legacy records** — absent field = registrant only (`drainPrincipalsOf`). **Update path:**
   re-`subscribe` is *not* an update path in this code (`_replay` refuses any different
   specification with `conflict`), so a small trusted host operation was added:
   `TaskBroker.setSubscriptionDrain(binding, { subscriptionId, drainPrincipals, policyIdentity? })`,
   replace-whole semantics, through the **registering** principal's binding with selectors covering
   the selection and a `subscribe` grant (what registering required); storage
   `ITaskRepositoryWriter.setSubscriptionDrain` (no-op writes nothing). Consequence, documented: a
   retry of the original `subscribe` after a change is `conflict` (strict, rather than silently
   answering a subscription that differs from what the retry asks for).
4. **`disposeWithheld` policy identity — built.** It fit: it rides the same specification field,
   converter, descriptor and update operation as 1–3. Shape: `ITaskAuthorization.policyIdentity?`
   (optional, so no implementer breaks; read once at binding and converted, so it travels with the
   policy object rather than with a free-floating bind parameter), `ISubscribeRequest.policyIdentity?`
   recorded on the subscription. `disposeWithheld` requires a recorded identity equal to the
   binding's; none recorded = refused for every binding. **Refinement:** the principal axis of
   `disposeWithheld` changes from "the registrant" to "a drain principal". The registrant rule was the
   round-3 answer to "anyone can bind"; with binding restricted to drain principals, and the policy
   axis closed by identity, the drainer is the right principal — in the host-subscribes /
   agent-drains pattern the agent's own policy is the consumer's, and the old rule made
   `disposeWithheld` unusable there except through the host's (broader) policy.
   `trustedKindAuthority` takes an optional `policyIdentity`.
5. **Testbed** — `subscribe` helper takes the drainer; every site names it (`agent:ada`, `agent:bob`,
   `host`); step 2 checks `agent:bob` binding `sub-ada` is `not-found-or-denied`; the unit test's
   check count moves 105 → 106 and the new check is pinned.
6. **Docs** — TSDoc on `subscribe`, `bindDelivery`, `setSubscriptionDrain`, the request types,
   `ITaskSubscription`, `ITaskAuthorization.policyIdentity`, `disposeWithheld`, the pump;

## Open questions

- **A receipt a removed principal prepared** stays issued and may be acknowledged by a principal
  still named, under *that* principal's authority — acknowledging what the removed one was shown.
  The host holds the receipt object, so this is host-reachable only; documented on
  `setSubscriptionDrain`. Should removal also abandon the removed principal's receipts? Manifests do
  not record who prepared them, so that would need a field on `IIssuedTaskReceipt`. Not built.
