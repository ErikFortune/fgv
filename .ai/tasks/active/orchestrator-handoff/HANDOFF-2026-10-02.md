## 4. How the outgoing orchestrator failed — the pattern, not a list of regrets

**A brief premise of mine was overturned in four of six streams, always the same way: I reasoned from a
plausible mechanism without reading the thing that implements it.**

| brief | my premise | what was actually true |
|---|---|---|
| I1c | expose the command schema as `toJson()` wire form | `IAiClientToolConfig.parametersSchema` must be an `ISchemaValidator`; JSON would mean a second validator that can disagree |
| tracked-commands | unify onto one validator | `JsonSchema` cannot express the converter's bounds, so a unified path runs both anyway — in series |
| I2 | bind the receipt by hash, or by composition identity | `IPromptComposition` has no identity at all; and the receipt's carrier would need `storage/` changes |
| M1 | a wide stop is bounded by `record-bytes` at 32 MiB | breadth is capped at **1,000 targets** by `defaultMaxStopTargets`, and a root is bounded by `maxTaskRecordBytes` = **8 MiB** |
| cluster-close | eighteen headlines would crowd the router and threaten its byte cap | the generator writes **full per-package history** and bounds only the router — at ten lines **regardless** of stream count |

**What contained the damage:** labelling options as *unverified candidates rather than a ranking*, and
telling the stream its job included deciding whether I was right. That worked every time — each stream
overturned me with a fact and shipped the better design. **Keep doing that.** But it is damage control,
not prevention: the cluster-close case cost a manufactured decision in a brief, and the fix was two
greps I should have run first. **Verify an option's feasibility before ranking it.**

**Four operational traps I hit personally:**

1. **Count by listing, not from memory.** I called this cluster twelve streams, then thirteen, then
   wrote "nineteen implementation slices" into a promotion PR. It is **eighteen** slices and twenty
   streams. Three errors of one kind. The habit that works is `git ls-tree | cat -n`, every time; the
   habit that fails is recalling a number I have already said out loud.
2. **Never run a revert matrix without `--pkg`** and a `node_modules` symlink. It mutates the package in
   place; I killed an accidental full run mid-row, left the mutant in the tree, and then diagnosed my
   own corruption as a defect in a merge. The runner's usage notes say this; I had not read them.
3. **GitHub's check-runs endpoint serves stale data.** I reported a CI run as "going on an hour" when it
   had finished in 14 minutes. Read the *job's own steps* (`actions_get` → `get_workflow_job`); step
   timestamps tell you whether it is genuinely progressing. Also check `head_sha` — a green run may
   belong to a commit two pushes ago.
4. **A squash makes a branch cut from the integration line unmergeable.** This handoff's own branch was
   cut pre-squash; merging it into the promoted `release` would have **resurrected the twenty
   `.ai/tasks/active/agent-tasks-*` directories** that cluster-close had just deleted. Recreate such a
   branch on the new base; do not merge it.

## 5. Lessons the cluster produced that belong in the substrate

Not yet codified beyond individual `result.md` files. The `mistakes-log` active stream is the natural
home; consider a lessons-codification pass
(`.ai/conventions/workflow/lessons-codification-triage.md`).

- **A revert-matrix row can be green while protecting the bug.** I1c's canonicalization fixture used a
  whitespace-trimming encoder — idempotent — so the defect (encoding twice) and the protection were
  indistinguishable, and the row "protecting" canonical encoding was pinning the bug. The existing rule
  covers rows red for the *wrong reason*; this is a row green for the *wrong protection*. Remedy:
  fixture values where right and wrong answers differ.
- **A rule written in one slice did not survive the next.** I1b-10 (capture the identity you will check
  *before* the `await`) was written up, given a matrix row, and reappeared one slice later as an I1c
  **high** in a new file. Prose carry-forward is too weak for rules of that shape; a shared helper would
  have made it structural.
- **Parallel streams worked, twice**, when surfaces were genuinely disjoint (I1d ∥ `tracked-commands`;
  M1 ∥ P1). Collisions were confined to shared substrate — ledger, plan, `TECH_DEBT`, `CAPABILITIES` —
  and resolved by merging whichever landed first. The merged tree must then be tested, because neither
  branch's own gates can see the combination. Worth repeating; worth *not* repeating where surfaces
  overlap.
- **Copilot's review trigger is unreliable and inconsistent.** On I1b four `request_copilot_review` API
  calls did nothing and a bare `@copilot review` comment worked. On I2 the reverse. **Try both and
  record which fired.**
- **Long Copilot loops are the expected shape on authorization boundaries**, not evidence of
  carelessness: I1c rounds 1 *and* 2 each found a real high. Stop on the finding *profile* going
  nitpicky, never on round count. `agent-tasks-cluster-close` stopped correctly at three — round 1 a real
  parser defect, round 2 a real artifact corruption, round 3 only stale counts it had itself introduced.

## 8. The user's own item

The System-1 / CLM-8B Phase A design (#710 above). Phase A is complete and found four things worth
knowing before Phase B:

- The "wrap the library" premise is **overturned**: CLM has no JS client, but the wire it implements
  (`POST /v1/systemone`) has an official one — `@typesafe-ai/sdk`. So this is the `ts-extras-ollama`
  shape (a Result boundary over an official client pointed at a sidecar), not a new integration shape.
- **No fgv interface**, because the wire *is* the interface and an interface would promise a semantic
  equivalence the servers do not have.
- **CLM-8B is not laptop-viable**: vLLM serving Qwen3-8B on an NVIDIA GPU, and the GGUF conversion is
  *heads only* — it still needs the 16.4 GB encoder.
- **Upstream CLM silently truncates the question** (2048 tokens from the end of the state, which is where
  the question sits). fgv will refuse at a mandatory per-call `inputLimit` and never truncate.

Design § 12 lists the open questions for Phase B, including two new ones the user's answers created
(OQ-10: what serves Qwen in deployment; OQ-11: which remote development compares against).
